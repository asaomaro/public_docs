# 要件: ナビゲーションまわりの改善 6 件

## 背景 / 課題

ユーザーから、`diff-review-html` の画面（`templates/`）について 6 件の追加指摘があった。
既存の実装を1件ずつ確認したところ、いずれも**未対応**（または一部だけ対応済みで足りない）と判明した。

1. **段差の一括展開が無い**。前後の隠れた行は 20 行ずつの段階展開（`↑`/`↓`）ができるが、
   その隙間を**一度に全部**開くボタンが、ファイル単位の「すべて展開」（`⏷`）とは別に、
   **その隙間の場所そのもの**には無い（GitHub にはある）。
2. **ツリー表示の長い名前が省略されない**。中間階層を 1 行にまとめる機能（`docs/a/b/c` のような
   連結）自体は既にある（`collapseSingles`）が、その行やファイル名が長いとき、
   `word-break: break-all` で**折り返す**だけで、`...` 省略＋ツールチップでの全体表示が無い。
3. **ペインの開閉ボタンがトップバーにある**。ファイル一覧・コメント一覧の開閉ボタンは、
   各パネル自身ではなく画面上部のトップバーに置かれている。閉じたパネルを再度開く操作が、
   パネルから離れた場所にある。
4. **ハイライトはあるが、一覧側が追従しない**。中央の差分をスクロールすると、いま表示中の
   ファイルは左の一覧でハイライトされる（前 work で対応済み）が、ファイル数が多く
   一覧側がスクロールを要する場合、**一覧の表示範囲は動かない**——ハイライトされた項目が
   画面外に出たままになる。
5. **検索・絞り込み欄がヘッダー扱いではない**。ファイル一覧の検索欄、コメント一覧の絞り込み欄は、
   それぞれの一覧をスクロールすると**流れて消える**。見出し（`.pane-head`）だけは固定されている。
6. **画面全体のスクロール位置を示すバーが無い**。`md-to-doc` skill が出す HTML には
   ページ最上部に細い進捗バー（クリックでその位置へ移動）があるが、`diff-review-html` には無い。

## 目的 / ゴール

上記 6 件を実装し、GitHub の PR 画面や既存の `md-to-doc` の使い勝手に近づける。
「読んでいる場所が分かる」「操作したい場所の近くに操作がある」という一貫した方針で直す。

## ユーザーストーリー

- US1: レビュアーとして、大きな隙間を持つファイルを読むとき、20 行ずつではなく**その隙間全体**を
  一度に開きたい（AC1）。
- US2: レビュアーとして、ツリー表示で深い階層やファイル名が長くても、一覧の幅を崩さずに
  読みたい。省略された名前は**ホバーで全体を確認**したい（AC2, AC3）。
- US3: レビュアーとして、ファイル一覧やコメント一覧を閉じたり開いたりする操作を、
  **そのパネル自身の場所で**行いたい（AC4, AC5）。
- US4: レビュアーとして、差分を読み進めるあいだ、左のファイル一覧が**自動でスクロールして**
  いま読んでいるファイルを常に見えるようにしてほしい（AC6）。
- US5: レビュアーとして、ファイルを検索している最中や、コメントを絞り込んでいる最中に
  一覧をスクロールしても、**検索・絞り込みの入力欄が流れずに残ってほしい**（AC7, AC8）。
- US6: レビュアーとして、差分全体のどのあたりを読んでいるかを、**一目で**把握したい（AC9, AC10）。

## スコープ

**対象**: `templates/page.html`・`templates/style.css`・`templates/ui.js`・`templates/app.js`。
既存の「読む」機能の強化であり、レビュー記録の JSON スキーマには触れない。参照専用でも
すべて動く（書き込みの導線ではないため）。

**対象外**:
- 生成側（Python: `diff_review.py` 等）の変更。
- 新しいキーボードショートカットの追加（既存の `[`/`]`/`{`/`}` 等はそのまま）。
- ペイン幅のドラッグ・リサイズ機構そのものの変更（`wireSeparator` は今回触らない）。
- モバイル幅（900px 以下・3 列が縦積みになるレイアウト）でのパネル開閉ボタンの再配置。
  縦積みレイアウトでは元から「閉じたら `display: none`」で全体を隠す設計であり、
  今回のパネル開閉ボタンの移設は**デスクトップ幅（3 ペイン表示）に限る**。

## 機能要件

- F1: 隙間の展開表示（`.expander`）に、既存の「↑ 20 行」「↓ 20 行」に加えて、
  **その隙間全体を一度に開く**ボタンを追加し、3 つを同じ行に並べる。
- F2: ツリー表示の名前（ディレクトリ・ファイルの双方。中間階層を連結した名前も含む）を
  1 行に収め、あふれた分は `...` で省略し、`title` 属性で全体を表示する。
- F3: ファイル一覧・コメント一覧の開閉ボタンを、トップバーから各パネル自身の見出し
  （`.pane-head`）へ移す。パネルを閉じているときは、閉じた細いパネルの領域自体に
  再度開くための同じボタンを表示する（新しいボタンを増やすのではなく、既存の
  開閉ボタン 1 つの見た目・配置先を状態に応じて変える）。
- F4: いま表示中のファイルのハイライトが、ファイル一覧のスクロール範囲外にあるときは、
  一覧側を自動でスクロールしてハイライトを表示範囲内に収める。
- F5: ファイル一覧の検索欄（`.filelist-tools`）、コメント一覧の絞り込み欄（`.cl-filters`）を、
  各パネルの見出し（`.pane-head`）と同様に、スクロールしても上部に固定する。
- F6: ページ最上部に、`#pane-center`（差分を読む領域）のスクロール位置を示す細い進捗バーを
  常設する。クリックするとその位置へ `#pane-center` がスクロールする。

## 非機能要件 / 制約

- 単一の自己完結した HTML・サードパーティ依存なし（既存方針を継続）。
- 決定論（同じ入力から同じ出力）を崩さない。
- 描画は `textContent` のみ（`innerHTML` を使わない。XSS 対策の継続）。
- 参照専用（`--readonly`）でもすべて動く（読む機能であり、書く導線ではない）。
- 既存のキー操作（`j`/`k`/`e`/`Shift+E`/`t`/`f`/`s`/`[`/`]`/`{`/`}`/`r`/`?`）の対象・挙動を変えない。
- アイコンだけのボタンには `title`/`aria-label` を付ける（既存方針の継続）。

## 完了条件（受け入れ基準）

- [ ] AC1: 隙間のある差分に、上下の段階展開ボタンと**並んで**、その隙間全体を一度に開く
  ボタンがある。押すとその隙間がすべて表示され、隙間の表示自体が消える。
- [ ] AC2: ツリー表示で、パネル幅に収まらない長さのディレクトリ名・ファイル名（中間階層を
  連結した名前を含む）が `...` で省略される（折り返して複数行になったり、パネル幅を
  超えて横スクロールが出たりしない）。
- [ ] AC3: 省略された名前にマウスを乗せると、`title` 属性により省略前の全体の名前が
  ツールチップで表示される。
- [ ] AC4: ファイル一覧・コメント一覧の開閉ボタンが、トップバーではなく各パネル自身の
  見出し部分にある。
- [ ] AC5: パネルを閉じると、閉じた（幅の狭い）パネル自身の領域に、再度開くための
  ボタンが表示される。
- [ ] AC6: 中央の差分をスクロールしていま表示中のファイルが変わったとき、そのファイルに
  対応するファイル一覧の項目が一覧の表示範囲外にあれば、一覧が自動でスクロールして
  その項目を表示範囲内に収める（すでに見えている場合は一覧を余計に動かさない）。
- [ ] AC7: ファイル一覧をスクロールしても、検索欄は常に一覧の上部に見えている。
- [ ] AC8: コメント一覧をスクロールしても、絞り込み欄は常に一覧の上部に見えている。
- [ ] AC9: ページ最上部に細い進捗バーがあり、`#pane-center` のスクロール位置に応じて
  バーの長さが変わる。
- [ ] AC10: 進捗バーをクリックすると、クリックした横位置に対応する位置へ `#pane-center` が
  スクロールする。
- [ ] AC11: 参照専用（`--readonly`）で生成した画面でも、AC1〜AC10 のすべてが同じように動く。
- [ ] AC12: 既存のキー操作（`[`/`]`/`{`/`}` を含む）が、パネル開閉ボタンの移設後も
  同じ対象・同じ挙動で動く。

## 未確定事項

- 進捗バーの色・太さは既存の `md-to-doc` の値（高さ 7px の透明な帯＋高さ 3px の
  `var(--accent)` バー）をそのまま流用する前提とする（見た目の一貫性より実装の単純さを優先）。
  デザイン上の異論が出れば design で見直す。
