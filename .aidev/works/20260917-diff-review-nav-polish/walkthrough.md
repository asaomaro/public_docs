# レビューガイド: ナビゲーションまわりの改善 6 件

> `templates/`（`page.html` / `style.css` / `app.js`）だけの変更。`ui.js` は無改造。
> 生成側（Python）は触っていない。

## 変更概要 / 目的

ユーザーから挙がった追加の指摘 6 件をすべて直した。

1. **隙間の一括展開ボタンが無い** → GitHub と同じ位置（`↑`/`↓` の間）に「すべて表示」ボタンを追加
2. **ツリーの長い名前が折り返す** → `...` 省略＋ホバーで全体を `title` 表示
3. **パネルの開閉ボタンがトップバーにある** → 各パネル自身の見出し（`.pane-head`）へ移設。
   閉じたパネルには同じボタンがそのまま残る（新しいボタンを増やしていない）
4. **一覧側がハイライトに追従しない** → いま表示中のファイルが一覧の表示範囲外に出たら
   自動でスクロールして追従（すでに見えているときは動かさない）
5. **検索欄・絞り込み欄が固定されない** → 見出しと同じ扱いでスクロールに追従しないようにした
6. **画面全体の進捗バーが無い** → `md-to-doc` skill と同じ見た目の細いバーを最上部に常設

## 重要ポイント（非自明な判断）

1. **パネル開閉ボタンは新設せず、既存の 1 個を移設しただけ**（decisions.md D2）。
   `ui.js` の状態管理コードは ID で要素を参照するだけなので、DOM 上の位置を変えても
   無改造で済んだ（diff 0 行）。
2. **移設そのものが、モバイル幅で「閉じたパネルを二度と開けない」退行を生みかけた**
   （decisions.md D3）。要件はモバイル向けの再設計を対象外にしていたが、この 1 点だけは
   移設の直接的な副作用として最小限に直した。480px 幅の headless Chromium で実測して確認。
3. **進捗バーは `#pane-center` を見る**（decisions.md D4）。参考にした `md-to-doc` は
   ページ自体がスクロールする 1 ペイン構成だが、この画面は 3 ペインでページ自体は
   固定高さ、`#pane-center` だけがスクロールする。新しい scroll リスナーを増やさず、
   前 work（現在ファイルのハイライト）で追加済みのリスナーに相乗りさせた。
4. **隙間の一括展開は既存の `expandAll` と同じ数式を使い回す**（`shown.top` を隙間の全長に
   設定するだけ）。新しい展開ロジックを書いていない。
5. **一覧のスクロール追従は `scrollIntoView({block:"nearest"})` 1 行**。
   「すでに見えていれば動かさない」という要件を、ブラウザの標準動作がそのまま満たす
   （可視判定を自前で書く必要が無い）。
