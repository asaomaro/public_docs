# 決定記録: 指摘を「書く」側の script

> autonomous モードのため、人間のゲートで確認するはずだった選択をここに残す。

## D1: アンカーの規則は生成側に 1 か所だけ置き、画面との一致をテストで固定する

- **決定**: `anchor_of` / `valid_anchors` を `diff_review.py` に置く。
  `comment` も `check --anchors` もここを呼ぶ。画面 `app.js:anchorOf` とは
  **互いを指すコメント**を書き、test 工程で**位置の集合が一致すること**を検査する（307/307）。
- **理由**: 書く側が独自の判定を持つと、画面と少しずつずれる。
  ずれ方が悪質で、**script は「書ける」と言い、画面は入れ物を用意しない**——
  指摘が黙って「位置不明」へ落ちる。エラーも警告も出ない。
- **他の案**: 画面の JS を生成側から読んで評価する → 依存が増え、Python だけという性質が壊れる。却下。
- **代償**: 同じ規則が 2 つの言語に書かれる。**一致をテストで縛る**ことで代償を引き受ける。

## D2: `--side` の既定は RIGHT。**推測ではなく規約**として決める

- **決定**: 片側しか無ければその側。**両側あるときは RIGHT**。文書に明記する。
- **理由**: 実測で、両側が有効になるのは**その行が置き換えられたとき**（10/297）。
  そこで「決められない」と落とすと、**いちばん指摘したい「書き換えた行」で必ず落ちる**。
  GitHub の REST も `side` の既定は `RIGHT` なので、揃えておけば驚きが少ない。
- **他の案**: 両側あるときは落とす → 上記のとおり実用にならない。却下。
- **代償**: 変更前の行を指したいときに `--side LEFT` を忘れると、反対側に付く。
  → 失敗しない分、**文書で目立たせる**（SKILL.md に専用の節）。

## D3: 検証は**書く前に全件**。落ちたら入力を 1 バイトも変えない

- **決定**: `--batch` でも 1 件でも、**全部検証してから 1 回だけ書く**。
  失敗の報告は**全件ぶん**まとめて出す（1 件目で止めない）。
- **理由**: 途中まで書かれた記録は、直すより作り直すほうが早くなる。
  また、AI が相手なので **1 往復で全部直せる**ことに意味がある——
  1 件ずつ報告すると、20 件の指摘に 20 往復かかる。
- **代償**: `--batch` の中で、**同じ実行の中で作ったスレッドには返信できない**
  （検証時点ではまだ存在しないため）。理由は出す。返信は別の実行にする。

## D4: 入力の種類を保つ（バンドル → バンドル、記録 → 記録）

- **決定**: 中身で判別し、**同じ種類で書き戻す**。既定は上書き、`--out` で別ファイル / 標準出力。
- **理由**: バンドルを渡したのに記録 JSON が返ると、後続（ビューアへ渡す等）が繋がらない。
  上書きを既定にするのは、AI が繰り返し呼ぶときに**積み上がる**のが自然だから。
- **代償**: 既定が破壊的。→ **検証に落ちたら書かない**（D3）ことで実害を抑える。

## D5: ファイル単位のコメントでも**パスの実在を見る**（review で見つけて追加）

- **決定**: `--line` が無くても、`--path` があればそのファイルが差分にあるかを確かめる。
- **理由**: 最初の実装は行のあるときだけ見ていた。**差分に無いファイルへのファイル単位コメントが
  素通りし**、画面では行のときとまったく同じく「位置不明」に落ちていた（実測）。
  「行の指定が無い」だけで、穴としては同じもの。
- **代償**: `--path` を使うなら差分が要る（記録 JSON なら `--repo`）。
  ファイル単位のコメントだけを書きたいときにも git が要ることになるが、
  **バンドルを渡せば要らない**ので実用上の負担は小さい。

## D6: `check --anchors` は**既定にしない**

- **決定**: 位置の実在を見るのは `--anchors` を付けたときだけ。
- **理由**: `check` は既存の呼び出し（skill・スクリプト）が既にある。
  既定の意味を変えると、**これまで通っていたものが落ちる**。
  また、位置の検証には差分が要るので、記録 JSON では `--repo` が必要になる——
  既定にすると「`check` に急に `--repo` が要る」ことになる。
- **代償**: 付け忘れると位置の穴を見逃す。→ `comment` 経由なら**必ず**見るので、
  手で書いたときだけの話になる。SKILL.md では `comment` を推す。

## D7: 失敗には必ず**手がかり**を添える

- **決定**: 実在しない位置なら「そのファイルで指摘できる位置」を**範囲に畳んで**出す
  （`RIGHT 1-40 / LEFT 10-12, 21`）。ファイルごと無ければ**差分にあるファイル名**を出す。
  反対側にあるなら「反対の側にならあります」と言う。
- **理由**: 相手は AI で、**次の 1 手を自分で決められる形**でないと往復が増える。
  「駄目」だけでは直しようがない。40 行のファイルで 40 個並べても読めないので範囲に畳む。
- **代償**: メッセージが長くなる。大きな `--batch` では特に。→ test-result に未確認として残した。
