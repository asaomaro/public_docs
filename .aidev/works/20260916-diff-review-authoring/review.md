# レビュー: 指摘を「書く」側の script

autonomous モードのため人間のゲートは無い。**自分の差分を、他人の差分として読み直した**記録。

## ラウンド 1

### must — ファイル単位のコメントでパスを見ていなかった

- **症状**: `comment <bundle> --path totally/made/up.py --body "x"` が**そのまま通る**。
  `check --anchors` も捕まえない。画面では「位置不明」欄に落ちる。
- **原因**: 検証を「`--line` があるとき」だけに掛けていた。
  行の実在は厳しく見ているのに、**パスの実在は行があるときしか見ていなかった**。
- **なぜ見落としたか**: 「アンカー＝行」と考えていた。
  実際には**ファイル単位のコメントもパスという位置を持つ**——
  画面の `slotFor()` は `file:<path>` の入れ物を探し、無ければ「位置不明」に落とす。
  行の場合とまったく同じ壊れ方をする。
- **直し**: `path_problem()` を切り出し、`--line` の有無に関わらずパスを見る。
  `check --anchors` も `line: null` のスレッドを見るようにした。
- **確認**: 終了コード 3・入力は 1 バイトも変わらない・差分にあるファイル名が出る。
  変異（この検査を外す）でテストが落ちることも確かめた。

### nit — `check --anchors` がファイルを 2 回読んでいた

- `read_record()` で読んだあと、`--anchors` のときだけ `load_record()` でもう一度読み、
  バンドルなら `validate_bundle()` も 2 回走っていた。
- `load_record()` に一本化した。**動作は同じ、読む回数が 1 回**。

## ラウンド 1 で見つけたが「直さない」と決めたもの

| 事象 | 判断 |
|---|---|
| `resolve_side()` が検証と適用で 2 回呼ばれる | どちらも**同じ関数**を呼ぶので食い違わない。結果を持ち回すと引数が増えて読みにくい |
| 記録 JSON で `--repo` を省くと落ちる（カレントで勝手に diff しない） | **黙って別の差分で検証するほうが危ない**。記録を書いた時点と違う差分で「実在する」と言ってしまう |
| `--batch` の失敗メッセージが長くなりうる | 全件報告は D3 の意図そのもの。長さが実害になるかは使ってみないと分からない（test-result に未確認として記載） |

## 設計との突き合わせ

| design で決めたこと | 実装 |
|---|---|
| 規則は 1 か所（§1・D1） | `anchor_of` / `valid_anchors`。画面との一致を 307/307 で固定 |
| `side` の既定は RIGHT（§1・D2） | `resolve_side`。変異でテストが落ちることを確認 |
| 全件検証 → 1 回書く（§3・D3） | 失敗時に入力の SHA-256 が変わらないことを実測 |
| 入力の種類を保つ（§4・D4） | バンドル → バンドル、記録 → 記録。テストで固定 |
| 失敗に手がかり（§5・D7） | 範囲に畳む・ファイル名を出す・反対側を示唆 |
| `check --anchors` は追加（§6・D6） | 既定の挙動は変えていない（テストで固定） |
| 画面は触らない | **1 行も触っていない**。既存 80＋34 件を再実行して確認 |

設計から外れた点は無い。**足りなかったのは D5（ファイル単位のパス検証）**で、
設計の「アンカー」の定義が行に寄りすぎていた。decisions に追記した。
