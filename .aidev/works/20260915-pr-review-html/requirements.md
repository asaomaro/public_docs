# 要件: ローカル差分を GitHub PR 風の HTML でレビューし、指摘を JSON で往復させる skill

## 背景 / 課題

AI エージェントにコーディングさせた後のレビューが、いまは二重に不便になっている。

- **読む側**：`git diff` のターミナル出力しか手元に無い。ファイルをまたぐ変更の流れが追えず、
  見落としが出る。GitHub に PR を出せば読める画面になるが、**まだコミットも push もしていない
  ローカルの差分**（unstaged / staged）には、その画面が存在しない。
- **返す側**：気づいた指摘をチャットに自然言語で書くと、**どの行の何を直すのか**が構造を持たない。
  AI は文脈から推測して直すことになり、指摘の取りこぼしと解釈違いが起きる。
- **逆方向（AI がレビューする場合）も同じ穴がある**：AI の指摘はチャットに流れて消え、
  人間が「どの指摘が残っているか」を一覧で確認したり、その場で返信したりできない。

つまり、**差分を読む画面**と**指摘を機械可読な形で往復させる器**が両方とも無い。

## 目的 / ゴール

- ローカルの差分が **GitHub PR 画面と同じ読み心地で読めている**状態。
- レビューの指摘が**構造化された JSON として双方向に往復している**状態
  （人間が画面で書いた指摘を AI が機械的に拾える／AI が出した指摘を人間が画面で確認して返信できる）。
- そのレビューで**何を指摘し、何に返信し、何が解決したか**が、チャット履歴を遡らずに
  **1 つの JSON から復元できる**状態。
- 上記が**追加の実行環境なしで**成り立っている状態（ブラウザで HTML を開くだけ／
  生成側は Python3 の標準ライブラリのみで、pip パッケージ・Node・npm を要求しない。`decisions.md` D9）。

## ユーザーストーリー

- US1: レビューする人間として、AI が書いた変更の差分を GitHub PR 画面と同じ形で読みたい。
  なぜなら、ターミナル出力より見落としが減り、ファイルをまたぐ変更の流れを追えるから。
  （受け入れ: AC1, AC2, AC-I3）
- US2: レビューする人間として、画面で書いた指摘を JSON として取り出したい。
  なぜなら、その JSON を AI に渡せば、指摘を口頭で言い直さずに、取りこぼしなく修正させられるから。
  （受け入れ: AC3, AC4, AC5, AC6, AC12）
- US3: AI エージェントとして、レビュー結果を規定の JSON で書き出したい。
  なぜなら、人間がその JSON を HTML に読み込んで画面で確認・返信でき、指摘がチャットに流れて
  消えないから。（受け入れ: AC6, AC8, AC11, AC13）
- US4: レビューを中断・再開する人間として、前回の JSON を読み込んで続きから見たい。
  なぜなら、レビューは一度で終わらず、往復のたびに前回の指摘と解決状態が失われては困るから。
  （受け入れ: AC7, AC8）
- US5: この skill を別のリポジトリでも使う人として、リポジトリ側に何も足さずに動かしたい。
  なぜなら、レビューのために対象リポジトリへ依存やツールを持ち込むのは本末転倒だから。
  （受け入れ: AC9, AC14）

## スコープ

### 対象

- **ローカル git 差分**の取得：unstaged / staged / 任意のコミット・ブランチ間（`<a>..<b>`）。
- **単一 HTML ファイルの生成**：外部 CDN 無し・オフライン・`file://` で開ける。
- **PR 画面相当の機能性**：変更ファイル一覧、ファイルごとの差分表示、
  **行 / ファイル / 全体**の 3 階層のコメント、コメントへの返信（スレッド）、
  スレッドの解決／未解決、**pending → submit**（Approve / Request changes / Comment）のフロー。
- **レビュー記録の JSON 書き出し・読み込み**（読み込みで記録が復元される）。
- **生成時の JSON 埋め込み**：AI が書いた JSON を与えると、その指摘が入った状態の HTML が出る。
- **書きかけの自動保存**（localStorage）と、その破棄手段。
- **生成スクリプトは Python3（標準ライブラリのみ）**で、決定論的に生成する（`decisions.md` D9）。
- 成果物は**新規 skill** として `docs/ClaudeCode/skills/` 配下に置き、
  HTML 出力 / JSON 作成 / JSON 読み取りの 3 機能を SKILL.md から辿れるようにする。

### 対象外

- **GitHub PR / API からの差分・コメント取得**（PR 番号を入力にする経路）。別 work で足す。
- **GitHub への書き戻し**（レビュー結果を実際の PR にコメントとして投稿する）。
- サーバの常駐、複数人の同時編集、認証、コメントの共有ストレージ。
- 構文ハイライト（今回は差分の追加/削除の色分けまで）。
- 差分そのものの編集（画面からコードを直す「suggestion を適用」相当）。

## 機能要件

- **F1 差分取得**：`git` から unstaged / staged / コミット範囲の差分を取り、ファイル単位・
  ハンク単位に構造化する。バイナリ・リネーム・新規・削除・モード変更を落とさない。
- **F2 HTML 生成**：自己完結した 1 ファイルを出力する。変更ファイル一覧（追加/削除行数つき）、
  ファイルごとの差分、ファイルの折りたたみ、追加/削除の色分けを持つ。
- **F3 コメント**：行 / ファイル / 全体の 3 階層でコメントを書ける。各コメントに返信でき、
  スレッド単位で解決／未解決を切り替えられる。
- **F4 提出フロー**：書いたコメントは pending として溜まり、最後に
  Approve / Request changes / Comment のいずれかを選んで一括提出する。提出単位（レビュー）と
  その判定・サマリ本文が記録される。
- **F5 JSON 書き出し**：スキーマ版・対象差分の識別情報・レビュー（判定・サマリ）・
  コメント・返信・解決状態を含む JSON を画面から取り出せる。
- **F6 JSON 読み込み**：同じ HTML にファイル選択またはドラッグ＆ドロップで読み込み、記録を復元する。
- **F7 JSON の事前埋め込み**：生成スクリプトに JSON を渡すと、その記録が入った状態の HTML を出す
  （AI → 人間の経路）。
- **F8 一時保存**：書きかけを localStorage に自動保存し、同じ HTML を開き直したときに復元する。
  復元を明示的に破棄できる。
- **F9 JSON の検証**：スキーマに合わない JSON を、理由を示して拒否する
  （AI が壊れた JSON を出したときに黙って通さない）。
- **F10 AI が読むための出力**：未解決の指摘を、AI が修正作業に使える形（ファイル・行・本文）で
  テキスト一覧として出せる。
- **F11 skill 化**：SKILL.md から「HTML 出力」「JSON 作成」「JSON 読み取り」の 3 経路と
  その使用例に辿り着ける。

## 非機能要件 / 制約

- **追加依存ゼロ**：生成側は **Python3 の標準ライブラリのみ**（pip パッケージ・Node・npm・jq に依存しない）。
  ブラウザ側は素の HTML/CSS/JS（フレームワーク無し）。
  ※ 当初は POSIX sh としていたが、JSON の検証（F9）と要約（F10）を script 自身が担うため
  design のゲートで Python3 stdlib に変更した（`decisions.md` D9）。
- **決定論性**：同じ入力からは同じ HTML / JSON が出る（時刻・乱数・ハッシュ順などの揺らぎを
  出力に混ぜない、または固定できる）。
- **オフライン**：生成物は外部へ 1 リクエストも出さない。`file://` で機能が欠けない
  （JSON の書き出し・読み込みが `file://` でも通ること）。
- **安全性**：差分・コメントの内容が HTML / JS として解釈されない（`<script>` を含む差分を
  読ませても壊れない・実行されない）。
- **文字コード**：日本語を含む差分・コメント・ファイル名が化けない（UTF-8）。
- **規模**：数千行規模の差分でもブラウザで実用的に開ける。
- **移植性**：対象リポジトリに何も追加せず、リポジトリの外から実行できる。
- **既存 skill 群の規約**に従う（SKILL.md の frontmatter、description の発火語の書き方）。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: 差分行（またはファイル・全体）のコメント欄は、対象の操作
      （行のボタン、またはキー操作）で開き、`Esc` で閉じる。**閉じても書きかけの本文は失われず**、
      次に同じ場所を開くと続きから書ける。破棄は明示操作でのみ行われる。
- [ ] AC-I2 確定 / 取り消し: 修飾キー＋`Enter`（および「コメントする」ボタン）で pending として確定し、
      「取り消し」で確定前の状態に戻る。取り消したコメントは JSON に残らない。
- [ ] AC-I3 キーボードだけで完結: 「ファイル/行を移動 → コメント欄を開く → 書く → 確定 → 一覧へ戻る」
      をマウス無しで通せる。提出（submit）まで同様に到達できる。
- [ ] AC-I4 フォーカスの行き先: コメント欄を開いたらフォーカスは入力欄へ移り、閉じたら
      **開く操作を行った行（トリガ）へ戻る**。
- [ ] AC-I5 既存の操作を妨げない: 入力欄でのキー入力・ホイールがページ側のショートカットや
      スクロールへ漏れない。ブラウザ標準の編集操作（選択・コピー・元に戻す）を奪わない。
