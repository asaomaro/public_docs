# 要件: `.dreview` を VSCode で開いて、同じ画面で読み書きする拡張機能

## 背景 / 課題

`diff-review-html` は差分とレビュー指摘を **1 枚の HTML** か **1 つの `.dreview` ファイル**にして
ブラウザで読む。生成と検証は Python の CLI `diff_review.py` が行う（サブコマンド `html`＝全部入り HTML、
`bundle`＝`.dreview`、`view`＝差分を持たないビューア、`check`＝検証、`comment` / `resolve`＝記録への追記）。
画面は `templates/` の HTML / CSS / JS で、CLI がそれを 1 枚に組み立てる。
work `20260916-diff-review-bundle` で、VSCode 拡張の**土台**
（`.dreview` 形式・差分を持たないビューア `view`・ホストがバンドルを書き込む空の `#bundle-data`・
`postMessage` での差し替え）までを作り、**拡張そのものは対象外**として残した
（同 work の requirements.md「対象外」、`SKILL.md`「エディタ拡張から使う（土台）」）。

いまの課題:

- **エディタの中で読めない**。`.dreview` を受け取ったら、ブラウザでビューアを開き、
  ファイルを選び直す必要がある。コードを書いている VSCode から離れることになる。
- **書いた指摘がファイルに戻らない**。HTML 版の書き込みはブラウザの `localStorage` に下書きとして
  残り、ファイルに戻すには JSON を書き出して CLI で取り込む手間がある。
  `.dreview` を「開いて・書いて・保存する」という、エディタで普通の流れにならない。
- **同じ画面を 2 つ作ると、片方だけ直る**。拡張のために画面や解析を別の言語で書き直すと、
  直近のラウンドで積み上げた修正（展開・スクロール・D&D 等）が片方にしか入らない状態が必ず生まれる。

## 目的 / ゴール

- `.dreview` を VSCode で開くと、**HTML 版と同じ画面**で差分とコメントが読める状態。
- その画面でコメントを書き、**`Ctrl+S` で `.dreview` に保存でき**、未保存・元に戻す・
  閉じるときの確認が**VSCode のほかのファイルと同じように働く**状態。
- ファイルが外から変わっても（CLI での追記・git の操作）、**開いている画面がそれに追従する**状態。
- 画面・検証・解析・正規形の書き出しの **HTML 版と VSCode 版で共通の実装（画面の JS）が 1 つしか無く**、
  HTML 版を直せば VSCode 版にもそのまま入る状態（拡張は「ファイル」と「画面」をつなぐだけ）。
  別言語の CLI（Python）はこれまでどおり自分の実装を持ち、画面の JS はそれと**同じバイト列**を出す
  （既存の記録の書き出しと同じ関係）。
- 受け取った `.dreview` を開いても、**その中身が実行されることは無い**状態。

## ユーザーストーリー

- US1: レビューする人として、`.dreview` を VSCode のエクスプローラーから開いて、その場で差分と指摘を
  読みたい。なぜなら、コードを書いているエディタから離れずにレビューを確かめたいから。
  （受け入れ: AC1, AC2, AC9, AC15, AC-I1, AC-I4）
- US2: レビューする人として、開いた画面でコメントを書き・直し・解決し、`Ctrl+S` でファイルに
  保存したい。なぜなら、書いた指摘がブラウザの中に閉じず、ファイルとして人や AI に渡せるように
  したいから。（受け入れ: AC3, AC4, AC5, AC6, AC7, AC-I2, AC-I3, AC-I5）
- US3: レビューを受け取った人（や AI）として、CLI の `comment` / `resolve` でファイルを書き換えたとき、
  開いている画面にそのまま反映されてほしい。なぜなら、開き直すとスクロール位置と現在行が失われ、
  どこまで読んだか分からなくなるから。（受け入れ: AC8, AC-I4）
- US4: この skill を保守する人として、画面の修正を 1 か所でしたい。なぜなら、HTML 版と VSCode 版で
  同じ処理を二重に持つと、片方だけ直って挙動が食い違うから。（受け入れ: AC11, AC12）
- US5: 他人から `.dreview` を受け取った人として、開いても何かが実行される心配をしたくない。
  なぜなら、`.dreview` は JS としても読める形をしており、開く操作に「実行」が混ざると困るから。
  （受け入れ: AC10）
- US6: 拡張を入れる人として、手元でビルドして入れられ、動くことを確かめる手段が欲しい。
  なぜなら、Marketplace に公開しない前提なので、入れ方と確かめ方が手元に無いと使えないから。
  （受け入れ: AC13, AC14, AC16）

## スコープ

### 対象

- `.dreview` を開く**専用エディタ**（VSCode の WebView）。既定で `.dreview` に関連付ける。
- 画面での**レビューの書き込み**（コメントの追加・返信・編集・削除・解決/未解決・説明コメント・
  レビューの提出と、その編集・削除）を、**その `.dreview` への編集**として扱う
  （未保存・保存・元に戻す・やり直し・閉じるときの確認）。HTML 版にしかない周辺の操作
  （別のファイルを開く・下書きを初期化・JSON を書き出す）の扱いは design で決める。
- ファイルの**外部変更への追従**（再読み込みせずに差し替える）。
- ビューア側（`templates/`）に、**ホストへ変更を知らせる口**と、**正規形のバンドルを書き出す処理**を足す
  （HTML 版と VSCode 版が同じ処理を使う）。
- 拡張のビルド・パッケージ（`.vsix`）・テスト（実機の VSCode を自動で起動するもの）。
- `SKILL.md` の「エディタ拡張から使う」節の更新（読み取り専用前提の契約に、書き込みを足す）。

### 対象外

- VSCode Marketplace への公開（publisher 登録・署名）。
- VSCode から**差分を作る**機能（git から `.dreview` を生成するコマンド）。いまは CLI で作る。
- GitHub との連携、複数人での同時編集。
- VSCode 標準の差分エディタ・SCM ビューとの統合（画面は既存のビューアを使う）。
- vscode.dev / VSCode for the Web での動作保証。
- HTML 版の見た目・操作の変更（VSCode 版のために必要な最小限の口を足すことを除く）。
- レビュー記録（`diff-review/2`）とバンドル（`diff-review-bundle/1`）の**形式の変更**。

## 機能要件

- **F1 開く**: `.dreview` を開くと専用エディタが立ち上がり、HTML 版と同じ画面で差分とコメントを出す。
- **F2 書く**: コメントの追加・返信・編集・削除・解決/未解決・レビューの提出（編集・削除を含む）・
  説明コメント（note）を、画面から行える。確定した操作は**その文書への編集**になる。
- **F3 保存**: 保存すると `.dreview` に書き戻す。書き戻す中身は**正規形**（`diff_review.py bundle` が
  同じ内容から出すものとバイト一致）で、`diff_review.py check` を通る。
- **F4 変えていなければ変えない**: 開いただけのファイルは、どんな形であっても書き換えない
  （編集していなければ未保存にならない）。正規形のファイル（`bundle` やこの拡張が書いたもの）は、
  変更を取り消してから保存してもバイト列が変わらない。正規形でないが読めるファイル
  （改行が CRLF になったもの・手で整形したもの等）は、**最初の編集で全体が正規形に書き換わる**
  （正規形と F4 がぶつかる場合は、編集した時点で正規形を優先する）。
- **F5 元に戻す・閉じる**: VSCode の元に戻す／やり直しで、確定した操作を取り消し・再適用でき、
  画面に反映される。未保存のまま閉じるときは VSCode 標準の保存確認が出る。
- **F6 外部変更への追従**: 開いている間にファイルが外で変わったら、画面を差し替える。
  スクロール位置と現在行を保つ（差分そのものが変わった場合を除く）。
- **F7 失敗を黙らせない**: 壊れている・別形式・版が違うファイルは、理由を画面に出す。
  テキストとして開き直す道（VSCode の「エディターを開き直す」）を塞がない。
- **F8 実行しない**: バンドルの中身を JS として評価しない。WebView で動くスクリプトは拡張に
  同梱したものだけに限る。外部へのリクエストをしない。
- **F9 共有**: 拡張が表示する画面は、`diff_review.py` がテンプレートから生成したビューアそのもの。
  描画・検証・解析・正規形の書き出しを拡張側（TypeScript）に写さない。
- **F10 配色**: 画面の配色が VSCode のライト／ダークに合う。

## 非機能要件 / 制約

- **実装を二重に持たない**（ユーザー指示）。HTML 版と VSCode 版で共有できる処理は共有する
  （対象は HTML 版と VSCode 版の間。Python の CLI は別言語として既存の実装を持ち続ける）。
  拡張の同梱物のうち画面にあたるものは**ビルドで生成**し、手で編集しない。
- **HTML 版の性質を壊さない**: 単一 HTML・オフライン・第三者ライブラリなし・Python3 標準ライブラリのみ・
  決定論的な生成物・描画は `textContent` のみ。
- **拡張の実行時依存はゼロ**（VSCode API と Node 標準だけ）。開発時の依存（TypeScript・型定義・
  テスト用ランナー・パッケージャ）は拡張のディレクトリに閉じ、リポジトリに `node_modules` を残さない。
- 保存は **UTF-8（BOM なし）・LF**。Windows で保存しても変わらない。
- 数 MB のバンドルでも、コメントの確定や保存で画面が固まらない（目安: 2 MB のバンドルで、
  コメントの確定から画面への反映まで 1 秒以内）。
- 信頼されていないワークスペースでも安全に開ける（実行しないので、開くこと自体は許してよい）。
