# 調査: 画面まわりの不備 7 件

> 実測は headless Chromium（Playwright 同梱・`file://` のまま）。入力は `tests/fixture_repo.py` が作る
> **固定のリポジトリ**（新規/削除/置き換え/先頭行から始まるハンクを含む）で HTML を生成して使った。
> コード側の原因は `templates/app.js` / `templates/style.css` / `templates/ui.js` を直読して特定した。

## 調査課題

1. ツリー表示が階層に見えない原因は何か（F1）。
2. 「畳む」が無いことの正確な現状（F4）。
3. アイコン化して安全な操作・迷う操作の線引き（F5）。
4. 「確認済み」をどこに・どう持たせるか（F6・F7）。
5. クリップボードへの書き込みは `file://` で動くか（F8）。
6. 展開でスクロールが飛ぶ、その**正確な原因**は何か（F10・この work の核心）。

## F1: ツリーが平らに見える理由（コード直読 → CSS 実測で確認）

`app.js:appendTreeChildren` は `.tree-item` と `.tree-group` を正しく入れ子で組み立てている
（DOM 構造は木になっている）。しかし `style.css` に**インデントの宣言が無い**——

```css
.tree-group { margin: 0; padding: 0; }   /* 子を親と同じ左端に描く */
```

**同じ左端に描かれるので、ツリーではなく平らな一覧に見える。** ARIA 上は `role=tree` で
正しく組まれているが、見た目がそれに追いついていなかった。

**実測**: `.tree-group { padding-left: 16px; border-left: 1px solid …; margin-left: 6px; }` を
3 階層のダミー DOM に適用し、各階層の `getBoundingClientRect().x` を測った。

| 階層 | x 座標 |
|---|---|
| 0（親） | 8 |
| 1（子） | 31 |
| 2（孫） | 54 |

**+23px ずつ複合して増えている**——ネストした `.tree-group` に同じ規則を適用するだけで、
深さに応じたインデントが自動的に積み上がる（CSS のボックスモデルの性質どおり）。
追加の JS ロジックは要らない。接続線（`border-left`）も同時に足せる。

## F4: 「畳む」の現状（コード直読で確認）

`expandAll(section, file)` は `expandState[file.path]` の各ギャップを
`{top: 全部, bottom: 0}` にして全展開する。**逆方向（`{top:0, bottom:0}` に戻す）関数が無い。**
`gapsOf()` は展開状態と無関係に常に同じギャップを返すので、
「すべて展開」ボタンは展開済みでも表示され続け、押しても意味の変化が無い。

→ **対になる `collapseAllGaps(section, file)` を新設**し、`expandState[file.path]` を空にして
再描画すればよい（`expandAll` とほぼ同じ形。展開量を 0 に戻すだけ）。

## F5: アイコン化の線引き（実測なし・既存の「例外」条項に基づく判断）

要件が明示する「アイコンで足りる例」（ツリー/フラット）と、
明示する「例外」（アイコンだけでは分かりにくいもの）を突き合わせた。

| 操作 | 判断 | 根拠 |
|---|---|---|
| ツリー/フラット | アイコン化 | 要件が明示する例そのもの |
| 左右ペインの開閉 | アイコン化 | 既存の `◧`/`◨` が既に方向を表す絵。末尾のテキスト（「一覧」「指摘」）だけ削れる |
| テーマ（OS/ライト/ダーク） | アイコン化 | 太陽・月・半月の組は他の多くのアプリで確立した idiom |
| ヘルプ（キー操作） | アイコン化 | 「?」は文脈非依存で通じる |
| ファイルの折りたたみ | アイコン化 | 開閉の三角（▸/▾）は本 skill のツリー twisty と揃える |
| 展開/畳む | アイコン化 | 要件 F5 が名指し。ツリー twisty と同系統の記号にすれば one-off の学習が要らない |
| パスコピー（新設） | アイコン化 | クリップボード操作は絵記号が広く通じる |
| split/unified | **文字のまま** | 「分割」「統合」という抽象概念は絵 1 つに落ちない。GitHub 自身も文字表示 |
| rich/source | **文字のまま** | 「rich」はこの skill 固有の語で、絵にすると別の意味に読める |
| 提出・書き出し・開く・開始 | **文字のまま** | 実行結果が重い主操作。誤タップの影響が大きく、明示が要る |

## F6・F7: 「確認済み」の持ち場所

前 work（decisions.md D5）で「画面の設定は記録に入れず、ブラウザに `localStorage` で持つ」
という前例が確立している（下書きと同じ扱い）。確認済みも同じ性質——
**その差分を見た人の進捗**であって、指摘の中身ではない。

`persist()` は既に `{state, drafts}` を `storageKey`（差分の digest を含む）へ書いている。
**`viewed` を同じオブジェクトに同居させれば**、新しい保存キーを増やさずに済み、
下書きと同じタイミング（`persist()` の呼び出し）で保存される。

## F8: クリップボードは `file://` で動くか（実測）

| 経路 | 結果 |
|---|---|
| `navigator.clipboard.writeText()`（許可を明示的に与えた場合） | 書き込める |
| `navigator.clipboard.writeText()`（**ページのクリックだけ**、許可を明示しない） | **例外で失敗**（`NotAllowedError` 系） |
| 上が失敗したときの `document.execCommand('copy')`（一時 `<textarea>` 経由） | **成功**（`isSecureContext: true` でも、`file://` では Clipboard API の暗黙許可が下りない） |

→ **`file://` では Clipboard API に頼れない。** 実際の利用者操作（クリック）だけでは
権限ダイアログも自動許可も来ず、素の `writeText` は失敗する。**`execCommand('copy')` の
フォールバックが実質的な本経路**になる（非推奨 API だが、offline・依存ゼロという制約の中では
これが唯一動く手段）。両方失敗したときはバナーで知らせ、テキストを選択状態にして
手動コピーの避難路を残す。

## F10: 展開でスクロールが飛ぶ、正確な原因（実測・この work の核心）

**症状を再現**: 4 つの展開ギャップを持つファイルで、3 番目のギャップの展開ボタンを
（画面中央に見えるようにスクロールしてから）クリックした。

| 測った項目 | 結果 |
|---|---|
| クリック前の `#pane-center` の `scrollTop` | 2681 |
| クリック後の `scrollTop` | **2211**（`-470px` 動いた） |
| クリック前、画面中央にあった文字 | `"2423+ util 24"`（コード行） |
| クリック後、同じ画面座標にある文字 | `"src/core/util.py"`（ファイルの見出し） |
| クリック後にフォーカスが当たった要素 | 1 番目のギャップの `↑` ボタン |

**原因はコードにあった**: `redrawFile(file)` が

```js
var next = section.querySelector(".expander button");   // 常に「そのファイル内で最初の」
if (next) { next.focus(); }                              // ボタンを無条件で focus する
```

`querySelector` は DOM 順で最初に一致した要素を返す。**クリックしたのが 3 番目のギャップでも、
再描画後は必ず 1 番目のギャップのボタンに焦点が移る。** ブラウザは「フォーカスされた要素が
見えていなければスクロールして見せる」既定動作を持つため、無関係な位置（1 番目のギャップ）へ
画面ごと引っ�張られる。`expandAll`（すべて展開）にも同型のフォールバック
（`currentRow` が無ければ `.expand-all` ボタンへ）があるが、こちらは対象がファイル内の
決まった 1 か所なので実害は小さい。**主犯は `redrawFile` の「最初のボタンに固定」。**

**直し方の候補を 2 つ実測した**:

1. **正しい対象を再取得する**（`data-gap` とクリックした方向を覚えておき、再描画後に
   同じギャップの同じボタンを探す）。対象が消えていれば（全展開済みなど）妥当な代替へ。
2. **`focus({preventScroll: true})` を使う**（ブラウザの自動スクロールそのものを止める）。

ダミー DOM で (2) を実測: スクロール位置 0 のまま、ビューポート外の要素へ
`focus({preventScroll: true})` を実行しても **`scrollTop` は 0 のまま変化しなかった**
（対して通常の `focus()` ならスクロールされるはずの状況）。この一手だけで「無関係な位置へ
飛ぶ」ことそのものは止められる。

ただし (2) だけでは**フォーカスの妥当性**（正しい要素を選べているか）は直らない
（見た目は動かなくなるが、キーボードの現在位置が違う場所にあるままになる）。
→ **両方を組み合わせる**: (1) で正しい対象を特定し、(2) の `preventScroll` で
「万一まだズレていても画面は動かさない」形にする。最後に、対象が実際に視界の外にあるときだけ
`scrollIntoView({block: "nearest"})` で最小限だけ寄せる（近いときは何もしない）。

## リスク

- **R1**: `preventScroll` はブラウザ実装依存（歴史的に Safari の対応が遅れていた）。
  対応していない環境では**旧来の挙動（自動スクロール）に戻るだけ**で、今より悪化はしない。
  正しい対象を再取得する（上記 1）だけでも「無関係な位置」への飛びは大きく減るため、
  2 つを重ねることで単一の対応状況に依存しない。
- **R2**: 検索でツリーを絞り込むと、一致したファイルの祖先ディレクトリを自動で開く必要がある
  （閉じていると一致ファイルが見えない）。既存の `treeOpen`（画面内だけの開閉状態）を
  検索中は上書きせず、**検索中は一致した経路だけを強制的に開いて見せる**方式にする
  （検索を消したら記憶していた開閉状態に戻る）。
- **R3**: 確認済みチェックボックスは「書く」操作ではないが、フォームコントロールの追加は
  `readonly` 生成物にも**同じ DOM 構造**で出る必要がある（既存の `rw:begin/end` の対象外にする）。
  生成側は触らないので、`page.html` の静的な `rw:` マーカーには影響しない
  （このチェックボックスは `app.js` が動的に作る要素であり、テンプレートの静的削除の対象外）。
- **R4**: 「確認済み」の状態は `viewedFiles` を `applyDiffData` でリセットする対象に含める
  （バンドルを差し替えたら前の差分の確認済みを引きずらない。展開状態やツリー開閉と同じ扱い）。
- **R5**: アイコンに変える既存ボタン（`btn-tree` 等）は `title` 属性を新設する
  （マウス利用者のホバー説明。`aria-label` だけだとスクリーンリーダー以外に伝わらない）。

## 結論（design への申し送り）

1. ツリーは CSS の 3 行（`.tree-group` へのインデント＋接続線）で解決する。JS 変更は不要。
2. 「畳む」は `collapseAllGaps` を新設し、`expandAll` と対のボタンにする。
3. アイコン化は F5 の表のとおりに線引きする。
4. 「確認済み」は `persist()` の保存物に同居させ、`applyDiffData` でリセット対象に含める。
5. パスコピーは `execCommand('copy')` を主経路とし、`navigator.clipboard` は使えれば使う
   （両対応。失敗時はバナー＋選択状態）。
6. 展開時のジャンプは「正しい対象の再取得」＋「`preventScroll`」＋「必要な時だけ `nearest`」の
   3 段構えで直す。`redrawFile` にギャップの手がかりを渡す形にシグネチャを変える。
