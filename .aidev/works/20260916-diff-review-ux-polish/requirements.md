# 要件: 画面まわりの不備を直す（ツリー表示・検索・折りたたみ・アイコン化・既読・コピー・展開時のジャンプ）

## 背景 / 課題

これまでの work で 3 ペイン・split・rich diff・書く側の script まで揃ったが、
**画面を実際に使うと目につく不備**が 7 件ある。利用者からの実地の指摘。

1. ファイル一覧の「ツリー」表示が、見た目はただのパス一覧のまま（階層が見えない）。
2. ファイル一覧に検索が無い。ファイルが多いと目で探すしかない。
3. 文脈の展開（すべて展開）はあるが、**畳み直す**手段が無い。
4. ボタンにテキストが残っていて、アイコンで足りる場面でも冗長（モダンさを損ねる）。
5. 「確認済み」を付ける手段が無く、全体件数・確認済み件数も見えない。
6. ファイル名クリックで折りたたみが開閉するが、展開ボタンと役割が被っている。
   パスをコピーする手段も無い。
7. 隠れたコードを展開すると、**無関係な位置へ画面が飛ぶ**。

## 目的 / ゴール

- ツリー表示が実際に階層として読める状態（インデント・接続線）。
- ワイルドカード・正規表現に対応した検索でファイルを絞り込める状態。
- 展開したものを畳み直せる状態。
- 文脈から読み取れるボタンはアイコンだけになり、紛らわしいものは文字を残す状態。
- 確認済みを付けられ、進捗（件数）が一目で分かる状態。
- ファイル名はコピー可能な情報として扱え、折りたたみとは役割が分かれている状態。
- 展開操作で**画面が動かない**（動いても最小限）状態。

## ユーザーストーリー

- US1: 多いファイルを一覧するレビュアーとして、階層構造を目で追いたい。
  なぜなら、パスが平らに並ぶと似た名前のファイルを見分けにくいから。（受け入れ: AC1）
- US2: 大きな差分を見るレビュアーとして、ファイル名の一部で絞り込みたい。
  なぜなら、100 ファイルの中から数件を探すのに目視は遅いから。（受け入れ: AC2〜AC5）
- US3: 文脈を読むレビュアーとして、広げすぎた表示を元に戻したい。
  なぜなら、展開しっぱなしだと差分の要点が埋もれるから。（受け入れ: AC6）
- US4: 画面を毎回使うレビュアーとして、意味の分かるボタンは文字無しで済ませたい。
  なぜなら、並んだテキストボタンは視認の邪魔になるから。（受け入れ: AC7, AC8）
- US5: 大きな差分を分割して見るレビュアーとして、どこまで見たかを憶えておきたい。
  なぜなら、途中で離脱して戻ったときに最初から見返すのは無駄だから。（受け入れ: AC9〜AC12）
- US6: 他のツールへパスを貼りたい人として、ファイル名からパスを取り出したい。
  なぜなら、エディタでそのファイルを開く・検索するのに正確なパスが要るから。（受け入れ: AC13, AC14）
- US7: キーボードで読み進めるレビュアーとして、展開のたびに画面を見失いたくない。
  なぜなら、読んでいた場所を見失うと読み直しになるから。（受け入れ: AC15, AC16）

## スコープ

### 対象

- ファイル一覧のツリー表示の見た目（インデント・接続線）。
- ファイル一覧の検索（部分一致・ワイルドカード `*`/`?`・`/正規表現/`）。
- ファイルの「畳む」（展開を元に戻す）操作。
- 意味の伝わるアイコンへの置き換え（ツリー/フラット・ペイン開閉・テーマ・ヘルプ・
  ファイルの折りたたみ・展開/畳む・コピー）。判断に迷うもの（split/unified 等）は文字を残す。
- 「確認済み」チェックボックスと、全体・確認済みの件数表示。
- ファイルパスのコピー機能。ファイル名クリックでの折りたたみ開閉の廃止。
- 展開操作でのスクロール位置維持。

### 対象外

- 生成側（Python）の変更。この work は画面（`page.html` / `app.js` / `ui.js` / `style.css`）だけ。
- レビュー記録 JSON の形式変更。「確認済み」は画面の状態であり、記録には入れない
  （既存の decisions.md D5〜D11 と同じ扱い）。
- 検索対象をファイル本文まで広げること（対象はファイルパスのみ）。
- 新しいキーボードショートカットの追加（既存キーの動作を壊さないことが優先）。

## 機能要件

- **F1 ツリーの見た目**: 深さに応じたインデントを付け、親子関係が視覚的に分かる。
- **F2 検索欄**: ファイル一覧の上に検索入力を置き、入力のたびに一覧を絞り込む。
  ツリー表示でも動作し、一致するファイルを含むディレクトリだけを残す。
- **F3 検索の記法**: 記号を含まない入力は部分一致（大小文字無視）。`*`/`?` を含む入力は
  ワイルドカードとして展開。`/…/` で囲まれた入力は正規表現として扱う（フラグ付与可）。
- **F4 畳む操作**: ファイルの「すべて展開」の対になる「折りたたむ」操作を用意する。
  展開済みの内容を初期状態（ハンク＋文脈のみ）へ戻す。
- **F5 アイコン化**: 次のボタンをアイコン（＋ `title`/`aria-label`）のみにする——
  ツリー/フラット切り替え・左右ペインの開閉・テーマ切り替え・ヘルプ・
  ファイルの折りたたみ切り替え・展開/畳む・パスコピー。
  意味が一目で伝わらないもの（split/unified 切り替え・rich/source 切り替え・
  提出/書き出し/開くなどの主要な操作）は文字を残す。
- **F6 確認済み**: ファイルごとにチェックボックスを置き、状態をブラウザに記憶する
  （差分ごと。既存の下書きと同じ scope）。ファイル一覧（フラット/ツリーとも）にも反映する。
- **F7 件数表示**: 「確認済み／全体」の件数を常に見える場所に出す。
- **F8 パスコピー**: ファイルヘッダーにコピー操作を置く。クリップボードへ書き込む
  （使えない環境では代替手段で書き込み、それも失敗したら失敗を伝える）。
- **F9 ファイル名クリックの整理**: ファイル名クリックでの折りたたみ開閉をやめる。
  折りたたみは専用のアイコンボタンで行う。
- **F10 展開時の位置維持**: 文脈の展開・畳み・すべて展開・折りたたむ、いずれの操作でも、
  操作前に見えていた内容が操作後もその場に留まる（大きく動かない）。

## 非機能要件 / 制約

- **単一 HTML・オフライン・第三者ライブラリなし**（既存の性質を維持）。外部アイコンフォント不可。
  Unicode の記号文字のみで表現する。
- **決定論**: 同じ入力から同じバイト列。確認済み・検索語などの画面状態は生成物に混ざらない。
- **XSS 非解釈を保つ**: 新しい描画も `textContent` のみ。検索語をそのまま正規表現化しないよう、
  ワイルドカード変換とユーザー指定正規表現の経路を区別し、危険な入力でも例外で落ちない。
- **アイコンにも到達可能な名前を持たせる**: `aria-label` または `title` を必ず添える。
- **既存キー割り当てを壊さない**（`f` キーはファイル折りたたみ、`e`/`Shift+E` は展開のまま）。
- **参照専用でも動く機能**: この work で足す検索・確認済み・パスコピー・畳む操作は
  いずれも「書く」操作ではないので、`--readonly` でも使える
  （既存の「読む機能は分岐に入れない」方針を踏襲。ツリー表示は前 work からの既存機能で、
  そちらも readonly 制約とは無関係にすでに動く）。

## 完了条件 (受け入れ基準)

- [ ] AC1: ツリー表示で、深いパスほど右にインデントされ、親子関係が視覚的に読み取れる。
- [ ] AC2: ファイル一覧の検索欄に文字を入れると、一致しないファイルが一覧から消える
      （フラット・ツリーの両方）。
- [ ] AC3: `*`/`?` を含む検索語がワイルドカードとして働く（例: `*.py` で拡張子を絞れる）。
- [ ] AC4: `/…/フラグ` の形の検索語が正規表現として働く。
- [ ] AC5: 記号を含まない検索語は大小文字を無視した部分一致で働く。
- [ ] AC6: ファイルの「畳む」操作で、そのファイルの展開状態が初期状態へ戻る。
- [ ] AC7: 一覧に挙げたボタン群がアイコンのみになり、`aria-label` または `title` を持つ。
- [ ] AC8: split/unified・rich/source など迷う操作は文字表示のまま残っている。
- [ ] AC9: ファイルの確認済みチェックボックスを操作すると、状態が保たれ再読み込みでも残る。
- [ ] AC10: 確認済みの状態がファイル一覧（フラット・ツリー）にも見える形で反映される。
- [ ] AC11: 「確認済み／全体」の件数がファイル一覧の近くに常時表示される。
- [ ] AC12: 確認済み状態はレビュー記録の書き出し JSON に含まれない。
- [ ] AC13: ファイルヘッダーのコピー操作でファイルパスがクリップボードに入る
      （クリップボード API が使えない環境でも代替手段で入る）。
- [ ] AC14: ファイル名をクリックしても折りたたみは開閉しない
      （折りたたみは専用のアイコンボタンでのみ行える）。
- [ ] AC15: 文脈の部分展開（↑/↓ 各ボタン）で、操作前に画面内に見えていた行が操作後も
      画面内に留まる。
- [ ] AC16: ファイルの「すべて展開」「折りたたむ」でも同様に、操作前後で表示位置が大きく動かない。

## 相互作用の受け入れ基準（UI を伴う work）

- [ ] AC-I1 到達性: 検索欄・確認済みチェックボックス・コピー操作・畳むボタンは、
      いずれもキーボード（`Tab`）で到達できる。
- [ ] AC-I2 状態の可視化: アイコン化したボタンも、状態（開閉・押下）が `aria-expanded` /
      `aria-pressed` などの属性で分かる。
- [ ] AC-I3 誤操作の防止: 検索欄にフォーカスがある間、既存のキー割り当て（`j`/`k`/`e` 等）が
      誤って発火しない。
- [ ] AC-I4 既存の操作を妨げない: `f`（折りたたみ）・`e`/`Shift+E`（展開）・`t`（rich/source）の
      キー割り当てが、この work のあとも同じ対象に対して働く。
