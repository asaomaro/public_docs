# レビュー: バンドルとビューアの分離

autonomous モードのため人間のゲートは無い。**自分の差分を、他人の差分として読み直した**記録。

## ラウンド 1

### must — 「ファイルを開く」にキーボードで到達できなかった

- **症状**: ビューアを開いた状態から `Tab` を **20 回**押しても「ファイルを開く」に届かない。
- **原因**: `<label for="file-import">` ＋ `hidden` な `<input type=file>`。
  **どちらもフォーカスを受けない**ので、タブ順に存在しない。
- **これは前 work から存在していた欠陥**（当時は「JSON を読み込む」）。
  この work で **AC-I3 を「実際に押す」検査として書いた**ときに初めて落ちた。
  「要素があること」を見る検査（AC-I1a）は通っていた——**存在は到達可能性ではない**。
- **直し**: 本物の `<button>` にして `input.click()` を呼ぶ。`.filebtn` の CSS は不要になったので削除。
- **確認**: `Tab` **9 回**で到達。検査も「存在」から「`BUTTON` かつ `tabIndex >= 0`」へ厳しくした。

### should — ファイルを開くたびにバナーが積み上がる

- **症状**: 壊れたファイルを 3 つ続けて開くと、バナーが 3 本並ぶ。画面の上半分が埋まる。
- **原因**: `banner()` が常に `appendChild` していた（前 work からの挙動）。
- **直し**: `key` を足し、同じ種類のバナーは**置き換える**。読み込み結果は常に 1 本。
- **確認**: 3 回失敗させてもバナーは 1 本、かつ**毎回その理由が出ている**
  （「バンドルとして読めません」「バンドルではありません」「JSON としてもバンドルとしても読めません」）。

### should — design の約束が実装で成り立たなかった（約束のほうを直した）

- **症状**: design に「`html` の出力はバイト単位で変わらない」と書いたが、
  テンプレートに口が増えたので**変わる**。
- **直し**: 約束を「**意味の不変** ＋ 既存 60 件が通ること」に改めた（`design.md` / `tasks.md` / D7）。
  隠して「変わっていない」と言うより、約束を現実に合わせるほうが正しい。

### nit — 埋め込み JSON を 2 回 parse していた

- **症状**: `boot()` が `readEmbedded("diff-data")` を 2 回呼んでいた
  （取り込み口の判定と、参照専用かどうかの判定）。
- **実測**: 1.9MB の埋め込みで 1 回 **6.4ms**。**体感できる遅さではない**が、
  同じものを 2 回読むのは単に無駄。
- **直し**: 1 回読んで使い回す。

### nit — 末尾の空白の扱いが生成側と画面側でずれていた

- **症状**: 画面側は末尾に余分な改行があっても読めるが、生成側 `parse_bundle` は落ちる。
- **なぜ問題か**: **ビューアでは開けるのに `check` が落ちる**という、
  利用者に理由が分からない食い違いになる。
- **直し**: 両方とも末尾の空白を許す（`;` で終わっていればよい）。回帰テストを追加。

### nit — `--load` のパスで `&` を弾いていた

- `&` はファイル名に入りうるので、弾くのは行き過ぎ。属性値として `&amp;` に退避する形に変えた。
  `"` `<` `>` は引き続き拒否（属性からの脱出を防ぐ）。

## ラウンド 1 で見つけたが「直さない」と決めたもの

| 事象 | 判断 |
|---|---|
| バンドルを切り替えると、前のバンドルの未保存分が警告なく消える | 下書きは**変更のたびに保存キーへ書いている**ので、実際には失われず、戻れば復元される。警告を足すと、正常な切り替えのたびに邪魔になる |
| `target` がバンドルの中で二重になる | 意図（D2）。検証を 1 本に保つための代償。MB 単位で数百バイト |
| `--from` と従来フラグの二重の書き方が残る | 既存の呼び出しを壊さないため（D5）。文書では `--from` を主に書いた |

## 設計との突き合わせ

| design で決めたこと | 実装 |

## ラウンド 2（deliver 後・利用者の指摘）

### must — ビューアが特定のファイル名を指すと、表示が決まらない

- **指摘**: 「テンプレート HTML が、どの `.dreview` を読むのか複数存在すると非確定になる」。
- **自分の見落とし**: D3 では `<script src>` の**危険**（実行されること）だけを見て、
  **決定性**を見ていなかった。この skill は「同じ入力から同じ出力」を性質として掲げているのに、
  配布物が**隣に何が置かれているか**で表示を変える形を作りかけていた。
  警告を出せば済む問題として扱ってしまった。
- **直し**: `view --load` と `__BUNDLE_SRC__` を**まるごと撤去**（D9）。
  取り込みは「ファイルを開く」「埋め込み」「ホストからの受け渡し」の 3 系統だけ。
- **副次的な効果**: **実行を伴う口が 1 つも無くなった**。research R1 は解消し、
  SKILL.md の WARNING を NOTE に落とせた。
- **確認**: 生成物 4 種の骨格に `<script src=` が 0 件、画面 3 種の `script[src]` が 0 個、
  外部リクエストは本体 1 件のみ（実測）。`--load` は argparse が弾く（終了コード 2）。
