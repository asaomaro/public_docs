# 要件: GitHub の差分・PR 差分を取得元として追加

## 背景 / 課題

ユーザーから「github差分、pr差分へ対応して」という追加指摘があった。

現状 `diff_review.py` の差分取得元（`--from`）は `unstaged` / `staged` / `range` / `commit` の
4 つで、いずれも**ローカルの git リポジトリ**が前提。CLI には `github-pr` という選択肢が
既に**予約**されているが（`SOURCES = (…, "github-pr")`）、`SOURCES_NOT_YET` により
「GitHub の PR からの取得はまだ実装していません」と理由を出して落ちるだけの未実装スタブである
（`diff_review.py:1461-1462`）。`SKILL.md` にも「GitHub の PR には触らない。PR からの差分・
コメント取得も、PR への投稿も行わない」と明記されている（`SKILL.md:375`）。

今回、この非対応を**取得の側だけ**外す。**投稿（コメントの書き戻し・レビューの提出）は
引き続き対象外**（従来の非目標のまま）。

## 目的 / ゴール

ローカルにリポジトリを clone していなくても、GitHub 上の PR、または任意の 2 リビジョン間の
比較（compare）を、そのまま `diff_review.py html` / `bundle` / `template` 等の入力にできるように
する。ローカル取得元と**同じ出力契約**（`target` / `files` の形）に変換し、既存の HTML 生成・
レビュー記録の仕組み（コメント位置の検証・JSON 往復）をそのまま使い回す。

## ユーザーストーリー

- US1: リポジトリを手元に clone していない状態でも、GitHub 上の PR 番号を指定するだけで
  その PR の差分をレビュー用 HTML にしたい（AC1, AC2, AC3）。
- US2: PR に紐付かない、GitHub 上の任意の 2 リビジョン間（ブランチ・タグ・コミット）の比較も、
  同様に取得したい（AC4, AC5）。
- US3: 非公開リポジトリや、未認証だと API のレート制限に掛かる場面のために、
  トークンを渡して認証付きで取得したい（AC6, AC7）。
- US4: 取得元が GitHub であっても、指摘の追加（`comment`）・検証（`check --anchors`）・
  一覧（`list`）など、既存の記録まわりの操作がローカル取得元と同じように使えてほしい（AC8）。
- US5: GitHub 側のエラー（存在しない PR・認証エラー・レート制限）が起きたとき、
  原因が分かる理由とともに失敗してほしい（黙って別の結果を返さない）（AC9）。
- US6: このツールの保守者として、GitHub 取得元を追加しても、既存のローカル取得元の挙動と、
  全文を持たないファイルの「展開できない」表示が、既存の仕組みと矛盾しないでほしい
  （AC10, AC11）。GitHub Enterprise 等、`api.github.com` 以外を向けたい利用者のために、
  ベース URL を差し替えられてほしい（AC12）。

## スコープ

**対象**: `diff_review.py`（差分取得元の追加）。既存の `templates/`（画面側）・
JSON スキーマ（`schema.md`）には触れない——`collect_diff` が返す `target` / `files` の形を
ローカル取得元と揃えることで、画面・記録まわりは無改造で動く前提。

**対象外**（今回のスコープ外。理由つき）:
- **GitHub への書き戻し**（レビューコメントの投稿・提出）。従来通り非目標のまま
  （`SKILL.md` の「PR への投稿は行わない」はそのまま維持し、「取得は行わない」の一文だけを改める）。
- **展開（段階展開・「すべて展開」）用の全文取得**。ローカル取得元は `git show` で旧/新の
  ファイル全文を取れるが、GitHub の PR/compare API はハンク単位の patch しか返さない
  （調査で確認。research.md F3）。全文が要る機能（前後の展開・シンタックスハイライトの
  ハンク外部分・rich diff）は、GitHub 取得元では**全文を追加で取得しない**前提とし、
  「展開できません」の理由を画面に出す既存の仕組み（`--expand-max-lines` 超過時の表示）を流用する。
  全文取得（Contents API を 1 ファイルごとに叩く）は API 呼び出し数が変更ファイル数に比例して
  増える別種のコストであり、別 work で検討する。
- **GitHub Enterprise Server（オンプレ版）固有の URL 形式**の自動判定。API のベース URL は
  明示指定できるようにするが、既定は `https://api.github.com`（GitHub.com 固定）。

## 機能要件

- F1: `--from github-pr` を実装する。`--github-pr <owner>/<repo>#<番号>` または
  PR の URL（`https://github.com/<owner>/<repo>/pull/<番号>`）のどちらでも指定できる。
  GitHub REST API から PR のファイル一覧（パス・状態・追加/削除行数・リネーム元・patch）と
  base/head のコミット SHA を取得し、ローカル取得元と同じ `target` / `files` の形に変換する。
- F2: `--from github-compare` を実装する。`--github-repo <owner>/<repo>` と
  `--rev <base>...<head>` で、PR に紐付かない任意の 2 リビジョン間の比較を取得する
  （GitHub の compare API・`base...head` の 3 ドット記法）。
- F3: 認証トークンを `--github-token <TOKEN>`、または環境変数 `GITHUB_TOKEN` / `GH_TOKEN`
  （この優先順）で受け取り、指定があれば API リクエストの `Authorization` ヘッダに使う。
  無指定でも動く（未認証。公開リポジトリのみ・レート制限は低い）。
- F4: GitHub Enterprise 等のために、API のベース URL を `--github-api-base <URL>` で
  上書きできる（既定 `https://api.github.com`）（AC12）。
- F5: 取得した差分は、ページ数（1 ページ最大 100 件）をまたぐファイル数でも**全件**取得する
  （API のページネーションに追従する）。
- F6: HTTP エラー・JSON として読めない応答・見つからない PR / リビジョンは、
  **黙って空の差分にせず**、状況が分かる理由（HTTP ステータス・GitHub からのメッセージ）を
  添えて失敗する。
- F7: `--repo`（ローカルリポジトリのパス）は `github-pr` / `github-compare` では**不要**にする
  （指定されていても無視ではなく、そもそも使わない——ローカル clone 前提を外すのが今回の目的のため）。
- F8: GitHub 取得元のファイルは全文を取得しない（スコープ外節）ため、`expand`（段階展開データ）を
  持たせない。画面側は「展開できない」を、既存の `--expand-max-lines` 超過時と**同じ表示**で扱う
  （GitHub 取得元専用の新しい文言・UI を追加しない）。
- F9: `github-pr` / `github-compare` の追加は、既存の取得元（`unstaged` / `staged` / `range` /
  `commit`）が通る関数・出力を変更しない形で行う（新しい分岐として追加し、既存経路には
  手を入れない）。

## 非機能要件 / 制約

- 追加の依存を増やさない。**標準ライブラリのみ**（`urllib.request`）で HTTP を行う
  （既存方針「pip パッケージ・Node・jq は不要」の継続）。
- ネットワーク呼び出しは `html` / `bundle` / `template` / `check --repo` /
  `comment`（`--repo` 使用時）など、**差分を取りに行く経路だけ**に閉じる。
  記録 JSON だけを検証する操作（バンドルを渡した `check` 等）に新規の通信を持ち込まない
  （バンドルは差分を内側に持っているため、従来通り通信不要）。
- 出力の決定論は「その時点の GitHub 上の内容に対しては決定論的」に緩める
  （ローカル git 取得元の「同じコミットなら何度実行しても同じ」はそのまま維持。
  GitHub 取得元は取得のたびに最新の PR/ブランチの状態を見に行くため、対象そのものが
  変われば出力も変わるのは当然の挙動とする）。
- トークンを引数（`--github-token`）で渡す運用は、シェル履歴・プロセス一覧に残る既知のリスク。
  環境変数での指定を優先する案内を `SKILL.md` に書く。
- 認証情報をログ・エラーメッセージに含めない。

## 完了条件（受け入れ基準）

- [ ] AC1: `--from github-pr --github-pr <owner>/<repo>#<番号>` で、公開リポジトリの PR の
  差分から HTML が生成できる。ファイル一覧・追加/削除行数・リネームの表示が、
  同じ PR をローカルで `git fetch` して `--from range` で見たときと一致する。
- [ ] AC2: `--github-pr` に PR の URL（`https://github.com/<owner>/<repo>/pull/<番号>`）を
  渡しても同じ結果になる。
- [ ] AC3: `--repo` を指定しなくても `--from github-pr` は動く（ローカルリポジトリ不要）。
- [ ] AC4: `--from github-compare --github-repo <owner>/<repo> --rev <base>...<head>` で、
  PR に紐付かない 2 リビジョン間の比較差分から HTML が生成できる。
- [ ] AC5: 100 件を超える変更ファイルを持つ PR / compare でも、全ファイルが一覧に出る
  （ページネーションの取りこぼしがない）。
- [ ] AC6: `--github-token` または `GITHUB_TOKEN` / `GH_TOKEN` 環境変数を指定すると、
  そのトークンで認証してリクエストする。
- [ ] AC7: トークン未指定でも、公開リポジトリの PR / compare は取得できる。
- [ ] AC8: GitHub 取得元で作った HTML / バンドルに対して、`comment` で指摘を追加し、
  `check --anchors` で位置を検証し、`list` で一覧にする一連の操作が、ローカル取得元と
  同じように（コード変更なしで）動く。
- [ ] AC9: 存在しない PR 番号・存在しないリビジョン・認証エラー・レート制限超過のいずれでも、
  差分を返さずに失敗し、HTTP ステータスと GitHub からのメッセージを含む理由が標準エラー出力に出る。
- [ ] AC10: 展開できない（全文を取得しない）ことが、画面上で既存の「展開できません」表示と
  同じ形で分かる（新しい専用の文言・UI を増やさない）。
- [ ] AC11: 既存のローカル取得元（`unstaged` / `staged` / `range` / `commit`）の挙動・出力は
  変わらない（回帰なし）。
- [ ] AC12: `--github-api-base` で API のベース URL を上書きできる（既定以外の値を渡すと、
  実際のリクエストがそのベース URL に対して行われる）。

## 未確定事項

- ページネーションの `per_page` は 100（API の上限）固定とする前提。要求元の PR が
  数百ファイル規模でも動くよう確かめる（design / test で具体的な件数を決める）。
- レート制限超過（HTTP 429 / 403 + `X-RateLimit-Remaining: 0`）時に、リトライを試みるか
  即座に失敗するかは design で決める（既定は「即座に失敗し、リセット時刻を理由に含める」を仮の方針とする）。
