# 要件: レビュー操作性の改善（ツリー見た目・レビュー提出フロー・固定ヘッダー・コメント折りたたみ・通知ベル）

## 背景 / 課題

`docs/ClaudeCode/skills/other/diff-review-html`（`templates/`）を実際に使ったユーザーから、
5 件の指摘があった。screenshot 2 枚が添付されている（1 枚目: 参考にしたいツリー表示の見た目、
2 枚目: レビュー提出のたびに通知バナーが画面上部に積み上がって消せない現状）。

1. **ツリー表示の見た目が参考画像と揃っていない**。現行のツリー（`appendTreeChildren` /
   `.tree-item`）はフォルダ・ファイルの区別が「▾/▸」の開閉記号だけで、アイコンが無い。
   検索欄（`#file-search`）も装飾のないテキスト入力のまま。
2. **レビュー操作ボタンの使い分けが分かりにくい**。現行はトップバーに「レビューを開始」
   （`#btn-start-review`）と「レビューを提出」（`#btn-submit-open`）という、ほぼ同じ動作
   （提出パネルの開閉）をする 2 個のボタンが常に並んでいる。加えて、提出した
   レビュー結果（`state.reviews` の各エントリ＝判定＋サマリ本文）を**後から見返す・
   編集する・削除する手段が画面に一切無い**（書き出した JSON を見るまで分からない）。
   そのため「未提出のコメントを破棄」ボタン（`#btn-submit-discard`）だけが誤りの
   やり直し手段になっている。
3. **長いファイルをスクロールするとファイルヘッダーが隠れる**。`.file-head`（パス・
   折りたたみ・確認済みチェック等）は `.file` の先頭に描かれるだけで固定されないため、
   ファイルの途中をスクロールしていると「いまどのファイルを見ているか」が分からなくなる。
4. **コメントを折りたたむ手段が無い**。全体コメント・ファイルコメント・行コメントの
   いずれも、スレッド（`.thread`）は常に全文表示される。コメントが増えると本文が長く
   並び、差分そのものが読みにくくなる。
5. **提出通知が蓄積して消せない**。`submitReview()` が呼ぶ `banner()` は `key` を渡さず
   呼ばれているため、提出するたびに `#banners` へ新しいバナーが積み上がり続け、
   ボタンの無いバナーには消す手段が無い（screenshot 2 で実測）。

## 目的 / ゴール

- ツリー表示が、使い慣れたエディタのソース管理ツリーに近い見た目になっている状態。
- レビューの「開始 → 結果入力 → 見返す/直す」が 1 つのボタンから迷わず辿れる状態。
- 提出済みのレビュー結果を画面上で確認・編集・削除できる状態。
- 長いファイルをスクロールしても、いま見ているファイルが常に分かる状態。
- コメントが増えても、読み終えたものを畳んで差分を読みやすくできる状態。
- レビュー提出などの完了通知が、画面上部を占領せず、後から一覧で確認できる状態。

## ユーザーストーリー

- US1: レビュアーとして、変更ファイルのツリーを使い慣れたエディタのツリー表示に近い
  見た目で確認したい。なぜなら、フォルダとファイルの区別が視覚的に一目で分かり、
  ファイル数が多い差分でも素早く目的のファイルを見つけられるから。（受け入れ: AC1, AC2, AC3）
- US2: レビュアーとして、レビュー結果を入力するボタンが 1 つだけあり、いま自分が
  「未着手/入力中」のどちらの状態か一目で分かるようにしたい。なぜなら、似た文言の
  複数ボタンが並んでいると、どちらを押せばよいか毎回迷い、誤操作にもつながるから。
  （受け入れ: AC4, AC5）
- US3: レビュアーとして、すでに提出したレビュー結果を後から見返し、書き間違いに
  気づいたらその場で直したり、不要になったものを消したりしたい。なぜなら、現状は
  提出した内容を画面上で二度と確認できず、JSON を書き出して中身を見るまで自分が
  何を提出したか分からないから。（受け入れ: AC6, AC7, AC8, AC9）
- US4: レビュアーとして、長いファイルをスクロールしている間も、そのファイルのパスや
  操作ボタンが見え続けてほしい。なぜなら、いまどのファイルをレビュー中か見失うと、
  コメントを付けている位置を勘違いしたまま書いてしまいかねないから。（受け入れ: AC10）
- US5: レビュアーとして、大量のコメントが並ぶ画面で、読み終えたコメントを畳んで
  隠したい。なぜなら、長いコメント本文がいくつも展開されたままだと、肝心の差分本体が
  埋もれて読みにくくなるから。（受け入れ: AC11, AC12）
- US6: レビュアーとして、レビュー結果を提出したときの通知は、ベルアイコンにまとめて
  あとで確認したい。なぜなら、繰り返し提出するたびにバナーが画面上部に積み上がり、
  消せないまま差分の閲覧スペースを圧迫するから。（受け入れ: AC13, AC14, AC15, AC16）

## スコープ

### 対象

- `templates/page.html` / `templates/style.css` / `templates/app.js` / `templates/ui.js`
  のうち、上記 5 件に関わる箇所。
- ツリー表示（`treeMode() === true` のとき）のアイコン・検索欄の見た目。
- レビュー提出まわりのボタン構成（`#btn-start-review` / `#btn-submit-open` /
  `#btn-submit-discard` と、それらが開く `#submit-panel`）。
- 提出済みレビュー結果（`state.reviews`）の一覧表示・編集・削除 UI。
- `.file-head` の固定表示（sticky）。
- コメントスレッド（`.thread`）の折りたたみ・展開。
- 通知（`banner()`）のうち「対応不要のお知らせ」系の、ベルアイコンへの集約。

### 対象外

- フラット表示（ツリー表示 OFF）のファイル一覧の見た目変更（アイコン化は対象外。
  今回の参考画像はツリー表示のみが対象）。
- ツリー行の追加/削除行数（`+N -N`）表示を、Git ステータスアイコンに置き換える／
  併記すること（decisions.md D2 のとおり、行数表示は維持し見た目だけ寄せる）。
- 通知の既読状態やベルの通知一覧をブラウザに永続化すること（セッション内で保持すれば
  よく、再読み込みで消えてよい。他の画面状態＝`viewModes` / `expandState` / `collapsed` /
  `treeOpen` / `fileSearchQuery` と同じ扱いに揃える）。
- 個々の行/ファイル/全体コメント（`comment`）自体の編集機能の新設（US3 が対象とする
  「編集・削除」は `state.reviews` の各エントリ＝判定とサマリ本文のみ。コメント本文の
  編集は既存どおり「取り消し」＋書き直しのままでよい）。
- サーバー連携・認証など、オフライン単一 HTML で完結するという既存の性質を変える変更。
- キーボードショートカットの新規追加（非機能要件を参照）。

## 機能要件

### F1: ツリー表示の見た目
- ツリーのフォルダ行にフォルダアイコン、ファイル行にファイルアイコンを表示する。
- ファイル検索欄（`#file-search`）に検索（虫眼鏡）アイコンを表示し、既存のテーマ変数
  （ライト/ダーク）に追従する角丸の見た目にする。
- 追加/削除行数（`+N -N`）の表示・ロジックは変更しない（decisions.md D2）。
- アイコンは既存の `.icon-btn` と同じ方針（絵文字ではなく、テーマ色に追従する記号/SVG）
  に揃える。

### F2: レビュー提出フローの単一ボタン化
- 初期状態ではレビュー操作ボタンは「レビューを開始」の 1 個だけを表示する。
- クリックすると、ボタンの表示が「レビュー結果を入力」に変わり、レビュー入力パネル
  （現行の `#submit-panel`）の開閉をトグルする。
- 独立した「レビューを提出」ボタン（`#btn-submit-open`）は無くす（F2 のボタン 1 個に統合）。

### F3: 提出済みレビュー結果の一覧・編集・削除
- レビュー入力パネルに、これまでに提出したレビュー結果（`state.reviews` の各エントリ:
  判定＋サマリ本文）を一覧表示する。
- 各エントリに「編集」操作があり、判定とサマリ本文を書き換えて保存できる。
- 各エントリに「削除」操作があり、削除するとそのエントリは無くなる。削除された
  レビューに紐づいていたコメント（`comment.review_id` が一致するもの）は「未提出」
  （`review_id: null`）に戻り、コメント自体は失われない。
- 「未提出のコメントを破棄」ボタン（`#btn-submit-discard` / `discardPending()`）は無くす
  （F3 により、提出前に一括で破棄しなくても、提出後に個別のレビュー結果を編集・削除
  すれば誤りを直せるため）。

### F4: ファイルヘッダーの固定表示
- 長いファイルをスクロールしている間、そのファイルの `.file-head`（パス・折りたたみ
  ボタン・確認済みチェック・タグ・操作ボタン）を画面上部（トップバー直下）に固定表示する。
- 次のファイルの見出しがその位置に達したら、前のファイルの見出しと自然に入れ替わる
  （GitHub の PR 差分画面と同様の挙動）。

### F5: コメントの折りたたみ
- 全体コメント・ファイルコメント・行コメントのいずれのスレッド（`.thread`）にも、
  折りたたみ / 展開を切り替えるボタンを付ける。
- 折りたたんだスレッドは、位置・解決状態・重大度などのヘッダー情報は見えたまま、
  コメント本文の一覧だけを隠す。

### F6: 通知のベルアイコン化
- トップバーに通知ベルアイコンのボタンを追加し、未読件数をバッジで表示する。
- 「対応不要のお知らせ」系バナー（ボタンを伴わない `banner()` 呼び出し。例:
  レビュー提出成功、バンドル/ファイルの読み込み成功）は、画面上部に直接表示せず、
  ベルの通知一覧に入れる（decisions.md D3）。
- エラーや選択を要するバナー（読み込み失敗、下書きが保存できない、下書き復元の選択、
  正規表現が不正 等、ボタンを伴う／即時の対応が要るもの）は、これまでどおり画面上部に
  表示する。
- ベルをクリックすると通知の一覧が開き、開いた時点で未読バッジをクリアする（既読）。

## 非機能要件 / 制約

- 新しいグローバルキーボードショートカットは追加しない（既存の「新しいキー操作は
  増やさない」方針を踏襲。折りたたみ・ベル等の新規ボタンは Tab 移動 + Enter/Space の
  既存経路で操作できれば足りる）。
- 描画は引き続き `textContent` のみで行う（`innerHTML` を使わない）。差分やコメントに
  何が入っていても HTML として解釈されない、という既存の約束を維持する。
- オフライン・単一 HTML ファイルで完結する既存の性質を維持する（外部フォント・外部
  スクリプト・外部 CSS を新たに読み込まない）。
- ライト/ダーク/OS 追従のテーマに新規要素（アイコン・ベル・固定ヘッダー・折りたたみ
  ボタン）もすべて追従する。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: レビュー入力パネルは「レビュー結果を入力」ボタンのクリックで
      開閉し、`Escape` でも閉じる（既存の `submit-panel` の閉じ方を踏襲）。コメント
      スレッドの折りたたみはボタンクリックでトグルする。通知ベルの一覧はベルアイコンの
      クリックで開閉し、`Escape` でも閉じる。
- [ ] AC-I2 確定 / 取り消し: 提出済みレビュー結果の編集は保存/キャンセル操作を持ち、
      キャンセルすると変更前の内容のまま残る。削除は既存の「取り消し」（コメントの
      キャンセル）と同様、確認ダイアログを挟まず即時に反映する（既存の操作感を踏襲）。
- [ ] AC-I3 キーボードだけで完結するか: 折りたたみボタン・通知ベル・レビュー結果の
      編集/削除ボタンは、いずれも Tab で辿り着き Enter/Space で操作できる（マウス無しで
      開く → 編集する/畳む → 確定する、まで通せる）。
- [ ] AC-I4 フォーカスの行き先: スレッドの折りたたみ/展開後もフォーカスは押した
      ボタン自身に残る。通知ベルを開いたあともフォーカスはベルボタンに残る（既存の
      ヘルプパネル `#btn-help-open` と同じ挙動に揃える）。
- [ ] AC-I5 既存の操作を妨げないか: 新規のボタン・パネルは、既存のキー操作
      （`j`/`k` の行移動、`[`/`]`/`{`/`}` のペイン操作 等）を奪わない。新規のグローバル
      キーショートカットは追加しない（非機能要件）。
