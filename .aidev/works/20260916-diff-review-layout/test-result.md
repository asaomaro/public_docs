## 3. 実装中に**実測で見つけて直した**もの

| 症状 | 原因 | 直し方 |
|---|---|---|
| コメント一覧へ Tab で届かない（60 回押しても） | `[` / `]` を「畳む」に使っており、移動の手段が Tab しか無かった | `[` / `]` を移動に、畳むを `{` / `}` に（下記） |
| ペインへ移動すると常に絞り込みの入力へ飛ぶ | `querySelector` のカンマは優先順位ではなく文書順 | セレクタを順に試す |
| 畳んでも幅が 1px 残る（`w=1`） | `box-sizing: border-box` のため、ペインの 1px 境界線が幅 0 を妨げる | 畳んだときは `border: none` |
| 狭い画面で横スクロールが出る（707 > 700） | 中央ペインの `display: grid` に列指定が無く、暗黙の列が max-content で決まって押し広げていた | `grid-template-columns: minmax(0, 1fr)` |
| ツリーの `↑` `↓` が差分の行送りも同時に起こす | ツリーのリスナが `preventDefault` しても `document` の処理が続いていた | `onKeyDown` の冒頭で `event.defaultPrevented` なら降りる |
| split と unified で同じ指摘の位置がずれる恐れ | split の左セルに「変更前の行番号」で位置を持たせようとしていた | 位置づけの規則を unified と**同一**にした（文脈行は右に 1 つだけ） |

### AC-I3 を実測して見つかった欠陥（この工程で修正）

最初の実装では `[` / `]` を「ペインを畳む」に割り当てていた。キーボードだけで一周する経路を
実際に押して確かめたところ、**差分の行から `Tab` を 60 回押してもコメント一覧に届かなかった**。
中央ペインの行 1 つ 1 つにコメントボタンがあり、DOM 順で右ペインはその後ろにあるためで、
**AC-I3（キーボードだけで完結）が実際には成り立っていなかった**。

畳む操作には他に 2 経路（トップバーのボタン・境界の `Enter`）があるが、**移動には経路が無かった**。
そこで `[` / `]` を「**そのペインへ移動**（畳んでいれば開く）」に変え、
畳むのは `Shift` 併用（`{` / `}`）に移した（`decisions.md` D8 に追記）。
修正後、`]` の **1 打鍵**でコメント一覧の項目にフォーカスが入る。

> ついでに見つけた実装の誤り: 移動先を
> `pane.querySelector('.cl-item, #cl-unresolved')` と書いていたが、
> `querySelector` はカンマ区切りを**優先順位ではなく文書順**で解決するため、
> 常に絞り込みの入力へ飛んでいた。順に探す形へ直した。

## 4. **前 work から残っていた欠陥**（この work で実測して修正）

**症状**: この repo の差分を HTML にしようとすると、**生成が永久に終わらない**（CPU 100% のまま返らない）。

**切り分け**: 走っているのは Python 自身（子プロセス待ちではない）→ 二分探索で
`.aidev/works/20260916-diff-review-rich/test-result.md` の 27 行目までで再現 →
その行は ```` ```gantt ```` のように**行の途中にフェンス記号がある行**だった。

**原因**: `markdown_nodes` の段落取り込みが「`_starts_block` に見える行」を 0 行返し、
位置 `i` が進まないまま `while` が回り続けていた。フェンスの正規表現は「行全体がフェンス」しか
受けないので、この行はどの分岐にも当たらない。

**修正**: 取り込みが 0 行なら 1 行を段落として消費し、**必ず前へ進める**。
修正後、同じ入力の生成は **0.3 秒**で完了する。回帰テストを 2 件追加（§1）。
