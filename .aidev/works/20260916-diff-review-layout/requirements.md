# 要件: レビュー画面を「3 ペイン＋切り替え」にする

## 背景 / 課題

`diff-review-html` は差分を読む機能（ハイライト・rich diff・段階展開）と、指摘を書く機能
（重大度・返信・説明）を持つところまで来た。**足りていないのは「画面の形」**——

- **差分の見比べ方が 1 通りしかない**。unified だけなので、置き換えが多い変更
  （リファクタ・整形）では「どの行がどの行になったのか」が読み取れない。
- **ファイルが多いと迷子になる**。一覧は平らな 1 列で、ディレクトリ構造が見えない。
  20 ファイルを超えると、どこを見ているのかが分からなくなる。
- **色は環境任せ**。OS の設定（`prefers-color-scheme`）に従うだけで、**その場で切り替えられない**。
  明るい部屋で暗いテーマのまま読む、逆も起きる。
- **指摘が差分の中に散らばったまま**。全体で何件あるのか、未解決がどれかを見るには
  差分をスクロールして探すしかない（`list` コマンドはあるが、それは画面の外）。
- **配置が縦一列**。ファイル一覧 → 全体コメント → 差分、と縦に積むので、
  一覧を見ながら差分を読むことができない。

## 目的 / ゴール

- 差分を **unified と split（左右 2 列）のどちらでも読める**状態。
- ファイルが多くても、**構造（ディレクトリ）で辿れる**状態。
- **見る人がその場で明暗を選べる**状態（OS 設定に従うことも選べる）。
- **指摘の全体像が 1 か所で見えて、そこから該当箇所へ飛べる**状態。
- **一覧・差分・指摘が同時に見えている**状態。かつ、狭い画面では邪魔にならないよう
  **畳めて、幅を変えられる**こと。
- 上記を足しても、**単一 HTML・オフライン・追加依存ゼロ・決定論**という性質が壊れていない状態。

## ユーザーストーリー

- US1: レビューする人間として、置き換えの多い差分を左右に並べて読みたい。
  なぜなら、unified では「消えた行」と「増えた行」の対応が目で追えないから。（受け入れ: AC1, AC2, AC3）
- US2: レビューする人間として、ファイル一覧をディレクトリの構造で見たい。
  なぜなら、変更がどの層に集中しているかは構造を見ないと分からないから。（受け入れ: AC4, AC5）
- US3: レビューする人間として、明暗をその場で切り替えたい。
  なぜなら、読む環境（時間帯・部屋の明るさ・共有画面）は OS の設定と一致しないから。（受け入れ: AC6, AC7）
- US4: レビューする人間として、指摘の一覧を見たい。
  なぜなら、「未解決が何件あるか」「重大度の高いものはどれか」を差分の中を探さずに把握したいから。
  （受け入れ: AC8, AC9, AC10）
- US5: レビューする人間として、一覧と差分と指摘を同時に見たい。
  なぜなら、行き来のたびにスクロール位置を失うのが読解の一番の妨げだから。（受け入れ: AC11, AC12, AC13）
- US6: 狭い画面で読む人として、左右のペインを畳んで差分だけにしたい。
  なぜなら、ノート PC の画面幅では 3 列だと差分が細くなりすぎるから。（受け入れ: AC12, AC14）

## スコープ

### 対象

- **split / unified の切り替え**（差分の表示形式）。
- **ファイル一覧のツリー / フラット切り替え**（ディレクトリで畳める）。
- **明暗テーマの手動切り替え**（ライト / ダーク / OS に従う の 3 状態）。
- **コメント一覧**（全スレッドの一覧・絞り込み・該当箇所へ移動）。
- **3 ペインのレイアウト**（左: ファイル一覧 / 中央: 差分 / 右: コメント一覧）、
  左右ペインの**開閉**と、**ドラッグによる幅変更**。
- 上記の選択を**そのブラウザに記憶する**（次に開いたときも同じ形）。

### 対象外

- 画面の設定を JSON（レビュー記録）に持たせること——**記録は指摘の器であって画面の設定の器ではない**。
- ペインの並べ替え・切り離し（ドッキング）。
- 差分の語単位ハイライト（split で「行のどこが変わったか」を色分けする）——今回は行単位まで。
- 生成側（Python）の出力形式の変更。**画面だけで完結させる**。

## 機能要件

- **F1 split 表示**: 左に変更前、右に変更後を並べる。削除と追加は同じ行に対応づけ、
  片側しか無い行は反対側を空にする。文脈行は両側に出す。
- **F2 split でのコメント**: 左右それぞれの行にコメントを付けられる（`side` が `LEFT` / `RIGHT` に対応）。
- **F3 表示形式の切り替え**: unified ↔ split をボタンで切り替える。rich 表示を持つファイルの
  rich ↔ source とは**独立**して働く。
- **F4 ツリー表示**: パスをディレクトリで畳んだ木にする。ディレクトリは開閉でき、
  各ファイルの追加 / 削除行数を出す。
- **F5 一覧の切り替え**: ツリー ↔ フラットをボタンで切り替える。
- **F6 テーマ切り替え**: ライト / ダーク / OS に従う の 3 状態を巡回するボタン。
  選択は記憶し、次に開いたときも同じ。
- **F7 コメント一覧**: すべてのスレッドを一覧にする。各行に位置・重大度・状態（未解決 / 解決済 / 説明）・
  本文の先頭を出す。
- **F8 コメント一覧の絞り込み**: 未解決のみ / 重大度 / 説明を含むか、で絞れる。
- **F9 コメント一覧からの移動**: 一覧の項目を選ぶと、該当するスレッドの位置へ画面が移動する。
- **F10 3 ペイン**: 左（ファイル一覧）・中央（差分）・右（コメント一覧）。
- **F11 ペインの開閉**: 左右それぞれを畳める。畳んでも開き直せる。
- **F12 ペインの幅変更**: 境界をドラッグして幅を変えられる。キーボードでも変えられる。
- **F13 記憶**: 表示形式・一覧の形・テーマ・ペインの開閉と幅を、そのブラウザに記憶する。

## 非機能要件 / 制約

- **単一 HTML・オフライン・第三者ライブラリなし**（既存の性質を維持）。
- **決定論**: 同じ入力から同じ HTML（画面の状態は実行時のもので、生成物には混ぜない）。
- **記憶はブラウザに閉じる**: `localStorage` を使い、**レビュー記録の JSON には入れない**。
  使えない環境（Firefox の `file://` 等）では既定値で動く（エラーにしない）。
- **キーボードで到達できる**: 追加する操作（切り替え・開閉・幅変更・一覧からの移動）は
  すべてキーボードだけで行える。
- **既存の性質を壊さない**: XSS 非解釈（`textContent` 描画）・UTF-8/LF・展開やコメントの既存機能。
- **狭い画面で壊れない**: 幅が足りないときは 3 列を積み重ねて表示する。

## 完了条件 (受け入れ基準)

- [ ] AC1: unified / split を切り替えられ、split では変更前と変更後が左右に並ぶ。
- [ ] AC2: split で、削除行と追加行が**同じ行に対応づく**（片側しか無い行は反対側が空）。
- [ ] AC3: split の行番号が左右それぞれ正しい（unified と同じ番号を指す）。
- [ ] AC4: ファイル一覧をツリーで表示でき、ディレクトリを開閉できる。
- [ ] AC5: ツリー / フラットを切り替えられ、どちらでもファイルを選ぶと差分の該当位置へ移動する。
- [ ] AC6: テーマを ライト / ダーク / OS に従う の 3 状態で切り替えられる。
- [ ] AC7: テーマの選択が**次に開いたときも保たれる**（記憶できない環境では既定で動く）。
- [ ] AC8: コメント一覧に、すべてのスレッドが位置・重大度・状態つきで出る。
- [ ] AC9: コメント一覧を未解決のみ / 重大度 / 説明の有無で絞れる。
- [ ] AC10: コメント一覧の項目を選ぶと、該当するスレッドの位置へ移動する。
- [ ] AC11: 左（ファイル一覧）・中央（差分）・右（コメント一覧）の 3 ペインで表示される。
- [ ] AC12: 左右のペインをそれぞれ畳め、畳んだあとも開き直せる。
- [ ] AC13: ペインの境界をドラッグして幅を変えられ、**変えた幅が次に開いたときも保たれる**。
- [ ] AC14: 幅の狭い画面では 3 列が積み重なり、差分が読める幅を保つ。
- [ ] AC15: split / ツリー / テーマ / ペインの状態が、**レビュー記録の JSON には入らない**
      （書き出した JSON が画面の設定を含まない）。
- [ ] AC16: 既存機能（段階展開・rich 表示・コメント・重大度・返信・提出・往復）が
      3 ペインでも同じように動く（回帰）。
- [ ] AC17: 生成物が決定論的で、外部リクエストが 0 件のまま（回帰）。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: ペインの開閉・ディレクトリの開閉・一覧の絞り込みは、
      いずれもキーボードで到達でき、状態が `aria-expanded` / `aria-pressed` で分かる。
- [ ] AC-I2 確定 / 取り消し: 幅の変更はドラッグ中に反映され、離した時点で確定する。
      キーボード（矢印キー）でも変えられる。
- [ ] AC-I3 キーボードだけで完結: 「ファイルを選ぶ → 差分を読む → コメント一覧から該当箇所へ飛ぶ →
      コメントを書く」をマウス無しで通せる。
- [ ] AC-I4 フォーカスの行き先: 一覧やコメント一覧から移動したとき、移動先に**フォーカスが移る**
      （スクロールだけして、キーボードの現在位置が置き去りにならない）。
- [ ] AC-I5 既存の操作を妨げない: 追加したキー割り当てが、入力欄・ボタン・既存のキー
      （`j` / `k` / `c` / `e` / `t` / `r` / `f` / `?`）の働きを奪わない。

## 未確定事項 / 確認したいこと

- **ツリーの確立したパターン**（`role="tree"` / `treeitem` / 矢印キーの規範）。→ research
- **テーマ切り替えの標準的な作り**（`data-theme` と `prefers-color-scheme` の共存）。→ research
- split の**行の対応づけ方**（削除と追加の組にする規則。既存の差分データだけで作れるか）。→ research
- 3 ペインと既存のスクロール（`scrollIntoView`）の相性。→ design
