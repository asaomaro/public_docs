# motion-video — 台本から、動画のように再生できる HTML を作る

同梱の `build.py`（Python3 / 標準ライブラリのみ）が、台本（JSON）・描画部（`engine.js`）・プレイヤーを 1 つの HTML にまとめる。
外部への依存は無い（書体は OS のもの、画像は data URI で埋め込む）。

- **描画は台本と時刻だけで決まる**。シーク・倍速・巻き戻しでも同じ画になり、同じ台本からは同じ動画になる。
- **字幕はナレーションから自動**で作り、場面の長さもナレーションと部品の最低の長さから決まる。音楽と効果音も時刻だけで決まる。
- **表現は 3 つから選ぶ**（台本の `expression`）。どれでも、プレイヤー・時間割・字幕・音声は同じ仕組み。

| 表現 | 映像の作り方 | 向く場面 |
|---|---|---|
| `components` 部品 | 用意された部品だけで組む。速く、毎回ぶれにくい | 定型の紹介・社内向け |
| `mixed` 混在（既定） | 基本は部品。見せ場の 1〜3 場面だけ `custom` で描く | ほとんどの紹介・説明 |
| `free` 自由 | 場面ごとに `custom`（Canvas）か `dom`（HTML・SVG・CSS）で描く | 作り込みたい・公開する動画 |

細かい仕様は `reference/` にある。**手順の中で「読む」と書いた資料は、その手順に入る前に Read で開く**（全部を先に読まない）。

## 手順

### 0. 素材を集める
- 何を紹介・説明する動画か、誰が見るか、元になる資料（README・docs・メモ・画面の画像）を会話とリポジトリから集める。
- 素材が足りなければユーザーに確認する（何を伝える動画か分からないまま作らない）。

### 1. 指示のフォームで聞く
ask-form スキルがあれば、`order.py` で 1 つのウィンドウにまとめて聞く（24 問。答えによって出し分ける）:

```bash
python3 <skill_dir>/order.py --subject "Sodashitsu の紹介" --out work/order.json
```

- 聞くこと: 何の動画か・資料・残したいこと・見る人・使い道・長さ・表現・プレイヤー（実物の画面の見本つき）・配色（色の帯）・背景（おまかせ／全場面の地を選ぶ／配色の地のまま。見本の画像つき）・ブランド・動きの性格・
  音の組み合わせ・声（VOICEVOX の話者は動いているものから）・話す速さ・曲・効果音・作るもの・確かめ方。
- 結果の `order.json`: `answers`・`spec`（台本の先頭の骨組み。おまかせの項目は書かれないので、内容から決める）・`build`（作るときの引数・長さの目安）・
  `warnings`（答えどうしの食い違い。**作る前にユーザーに伝える**）・`note`・`comments`（質問ごとの自由記述。その質問の答えへの条件として読む）。
- 引数や会話で決まっている項目も、フォームの既定に入れて確かめてもらう。前回の答えは次回の既定になる。 プレイヤーと動く背景の見本の画面は初回に Chrome で撮る（数秒）。
- 背景の答え（`answers.bg`）: `auto` は `reference/backgrounds.md` の選び方で内容から決める。`pick` は `spec.bg` が全場面の地（見せ場だけ替えるかは内容から）。`theme` は `bg` を書かない。
- 終了コード 3（ウィンドウを出せない・画面の前に人がいない）・ask-form が無いときは、**`reference/choices.md` を読み**、`AskUserQuestion` で聞く。

### 2. 台本を書く
`python3 <skill_dir>/build.py --list` で部品と書き方を確かめ、台本（JSON）を書く。骨組み:

```json
{
  "title": "動画の題名（ページの見出しにも出る）", "description": "ページに出す一文", "lang": "ja",
  "player": "studio", "theme": "navy-brass", "motion": "gentle", "expression": "mixed", "brand": { "name": "右上に出す名前" },
  "audio": { "narration": true, "music": "calm", "sfx": true, "pronounce": { "Sodashitsu": "ソーダシツ" },
             "voice": { "engine": "voicevox", "speaker": "四国めたん", "speed": 1.1 } },
  "chapters": [ { "title": "章の名前", "desc": "チャプターの一覧に出す説明",
                  "scenes": [ { "type": "title", "title": "…", "narration": ["…", "…"] } ] } ]
}
```

読む資料: **`reference/scenes.md`**（内容 → 部品）・**`reference/narration.md`**（ナレーション）・**`reference/motion.md`**（動き）・**`reference/sound.md`**（曲と効果音）。
背景を替えるなら `reference/backgrounds.md`、`custom`・`dom` で描く場面があれば **`reference/custom.md`**、2 人の掛け合いを直に書くなら `reference/talk.md`（ふつうは yukkuri-kaisetsu スキルを使う）。

いつも守ること:
- **章と場面**: 章は 4〜7 個、1 章に場面 1〜3 個（短め 4 章・場面 5 前後、標準 6 章・場面 8〜10、長め 7 章・場面 15〜25）。最初は `title`、最後は `end`。同じ部品を 3 場面続けない。
- **ナレーション**: 1 場面に 1〜2 文、1 文は 34 字前後まで。`narration` は文ごとの配列で書く。画面の文字とナレーションを同じ文にしない（画面は要点の語）。
- **項目を順に出す部品**（`bullets`・`steps`・`cards` など）は、**項目の数と字幕の数をそろえる**（i 番目の項目が i 番目の文で出る）。
  34 字を超える文は読点で字幕が 2 つに分かれて数がずれるので、短く書く。
- **動きの性格（`motion`）を 1 つ選ぶ**（内容と見る人から決める。ユーザーの指定があれば従う）。選んだら台本全体の `transition` は書かず、見せ場の場面だけ変える。強い動き（揺れ・破片・`slam`）は見せ場だけ。
- **曲は内容と雰囲気から選び、毎回同じにしない**。3 分を超えるなら、章の `music` で山場と締めの曲を替える。
- **表現ごと**: `components` は部品と `overlays`・`camera` だけ。`mixed` は、まず `overlays`（注記・矢印・強調・通知など）と `camera` で足りないかを考え、足りない見せ場だけ `custom`。`free` は各場面を `custom` で描く（`title`・`end` は部品でよい）。
- 誤読しやすい語（製品名・英字のコマンド）は `audio.pronounce` に読みを入れる（字幕は元のまま）。英字・数字の前後の空白は、声に渡す前に自動で詰める。

### 3. 確かめて作る

```bash
python3 <skill_dir>/build.py spec.json --readings      # 声を作る前に、読み（VOICEVOX のかな）と読み違えやすい所（! の行）を見る
python3 <skill_dir>/build.py spec.json --timeline      # 場面の長さ・字幕の時刻・合計（HTML は作らない）
python3 <skill_dir>/build.py spec.json -o out.html      # HTML を作る（--player・--theme で上書き可。audio.voice が VOICEVOX なら、動いていれば声も入る）
python3 <skill_dir>/check.py spec.json --shots         # 作った後に、数えて確かめ、全場面を撮る（必ず）
```

声・配布用（`--dist`）・YouTube や編集ソフト向けの書き出し（video-export スキル）は、**`reference/voice.md` を読む**。

- **声**: VOICEVOX で前もって作ると、場面の長さと字幕の時刻が声の長さで決まり、WebM にも声が入る（声 1 分で約 4MB）。声は 1 文ずつ作り、長い文は字幕だけを読点の息継ぎで切り替える。
  VOICEVOX が止まっていると warn が出て、その HTML はブラウザの声（別の声）になる。**`--readings` の `!` は声を作る前に直す**。
- **`--timeline`**: 合計の長さが選んだ長さに収まるか、字幕の切れ方が不自然でないかを見る。エラー（不明な type・必須の項目の欠け・画像が無い）は台本を直してから作り直す。
- **`check.py`**: 構成・項目と字幕の数・画面とナレーションの重なり・読み・HTML の中の声・長さ（`order.json` が同じ場所にあれば、その答えと比べる）を数え、`<台本名>.check.md` に書く。**直す所が 0 件になるまで直す**。
- **`--shots`** の一覧（`<台本名>_check/sheet.jpg`。撮るのは `shoot.py`: 絵が読み終わって描かれるのを待ち、一色の画面は撮り直す。それでも一色なら warn）を Read で見て、文字のはみ出し・重なりを直す。直すのは台本の文言・項目の数・`custom` の JS で、`engine.js` は触らない。`custom` の場面は途中の画も 2〜3 点見る。
- 公開する動画・3 分以上の動画は、**別のエージェントに `review.md` の観点で見てもらう**（作った本人は見落とす）。直したら 2 回目まで。

### 4. 渡す
- 出力した HTML の場所を伝える（`SendUserFile` で渡すと確かめやすい）。プレイヤーの操作の案内が要れば `reference/player.md`。
- 声を前もって作らなかったときは「読み上げの声は見る人のブラウザと OS のものを使う（声が無い環境では効果音と音楽だけ）」と添える。
  VOICEVOX で作ったときは、話者（キャラクター）ごとの利用規約とクレジットの表記を確かめるよう添える。
- ほかの HTML や md-to-doc の文書に入れるなら `reference/embed.md`。

## 直すとき

- **`engine.js`・`build.py`・`sound.py`・`voice.py`・`kaisetsu.py` を変えたら、回帰テストを回す**: `python3 -W ignore::ResourceWarning -m unittest discover -s ../tests -t ../tests`（この SKILL.md の場所から。3 秒ほど。素材と VOICEVOX は要らない）。motion-video と yukkuri-kaisetsu は `engine.js` を共有するので、片方の変更がもう片方を壊す。中身と足し方は `../tests/README.md`。
- テーマ・部品の足し方は `reference/notes.md`。曲・効果音の足し方は `reference/sound.md`。背景の足し方は `reference/backgrounds.md`（SVG は `bg_make.py` を回して作る）。
- SKILL.md には手順と、毎回守ることだけを書く。仕様の詳しい説明・一覧は `reference/` に置く（SKILL.md は呼ぶたびに読み込まれるため）。
