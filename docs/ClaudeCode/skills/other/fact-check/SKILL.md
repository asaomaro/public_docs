# fact-check — 書かれた事実を、出どころと照らす

文章 → 主張を抜き出す → 出どころを開き直して引用を取る → 判定 → 直し方。作るのは `<名前>.factcheck.md`（主張ごとの判定の表）。

この手順が防ぐのは、次の 4 つ。

- **書いた本人が確かめる**: 自分の書いたものは、合っている前提で読んでしまう。
- **記憶で確かめる**: 「知っている」は根拠にならない。出どころを開き直す。
- **要約を信じる**: ページを読む道具（`WebFetch`）は、言い換えたり、書かれていない数字を作ったりする。原文の引用を取り、機械で照らす。
- **写しの写しを信じる**: まとめサイトどうしが同じ誤りを写し合っている。元をたどる。

## だれが確かめるか

- **自分が書いた文章**（このセッションで調べて書いたもの・ほかのスキルで作った台本）: **別のエージェントに渡す**（`Agent` で、型は `general-purpose`）。
  渡すのは、文章のパス・出どころの一覧（あれば）・このスキルの場所だけ。「合っているはず」「ここは確認済み」といった自分の結論は書かない。
  ```
  <skill_dir>/SKILL.md の手順どおりに、<文章のパス> をファクトチェックしてください。
  出どころの一覧: <facts.md のパス。無ければ「なし」>。深さ: <ざっと／ふつう／念入り>。
  結果は <名前>.factcheck.md に書き、判定の数と、文章を直す所（主張・判定・根拠・直し方）を報告してください。文章そのものは直さないでください。
  ```
  返ってきた判定は、根拠の引用を自分でも 2〜3 個開いて確かめる（確かめ役の誤りも起きる）。
- **人から渡された文章**: 自分でこの手順を行う。

## 手順

### 0. 深さを決める

| 深さ | 確かめる範囲 | 使う場面 |
|---|---|---|
| ざっと | 危なさの高い主張（数字・年・言い切り）を 10 件まで | 会話の中の短い答え、下書き |
| ふつう（既定） | 候補を全部。大事な主張（題・結論・山場の数字）は 2 つの出どころで | 台本、人に渡す資料 |
| 念入り | 全部を 2 つの出どころで。一次情報まで たどる | 公開する記事・動画、お金や健康や法律の話 |

### 1. 主張を抜き出す

```bash
python3 <skill_dir>/claims.py extract <文章> -o <名前>.factcheck.md
```

- 数字・年・言い切り・比べる・原因・「〜が〜した」・引用・今の状態・説明の文 を拾い、危なさの高い順に並べた表のひな形ができる。
  台本なら、題・概要・サムネイルの文字と、画面に出す言葉・絵の名札も拾う（絵が中身と合っているかも対象。男性の人物に女性の絵、など）。
- **道具は拾い切れない**。文章を頭から読み、数字の無い事実（「〜は〜である」「〜が原因で〜になった」）を、表の最後に足す。
- 1 つの文に主張が 2 つあれば、`### C6a`・`### C6b` に分けて書く（「1869 年にティンダルが見つけた」は、年と人の 2 つ）。
- 同じ主張が別の場所にもあれば（画面とせりふ、本文とまとめ）、2 つ目からは `- 同じ: C6` とだけ書く（判定・根拠・出典は要らない。直し方は書く）。
- 題・見出し・結論・図や画面の文字も対象。目立つ所の誤りほど響く。

### 2. 主張ごとに確かめる

1. **出どころを開き直す**。文章に出典が付いていれば、まずその出典が**本当にそう言っているか**を見る（出典があることと、出典が正しく写されていることは別）。
   原文は `python3 <skill_dir>/claims.py page <URL>` で、要約を通さずに読める（`| grep -n 言葉` で探す）。
2. **原文をそのまま引用する**（日本語でも英語でも、言い換えない）。引用は機械で照らす:
   ```bash
   python3 <skill_dir>/claims.py quote <URL> "引用した文"
   ```
   `NG` なら、その文はページに無い（要約の道具が作った可能性が高い）。ページを開き直して取り直す。
   表のセルをまたぐ引用は、セルの間を空白にして書く（`blue 450–485`）。引用は 1 文か、その一部にする（長いと当たりにくい）。
3. **数字は計算し直す**。割合・倍率・差・合計・単位の換算・年数は、自分で式を立てて計算する（`python3 -c`）。出どころの要約に出た計算結果を写さない。
4. **大事な主張は、別の出どころでも確かめる**。同じ元を写しているもの（ウィキペディアと、それを写したサイト）は 1 つと数える。
5. **いつ時点の話か**を見る。統計・制度・価格・「世界一」は変わる。ページの日付と、文章の言い方（「今は」）が合っているか。
6. 出どころの強さ: 当事者の一次情報・公的機関・学術・査読のある資料 ＞ 百科事典・大手の報道 ＞ 専門家個人の解説 ＞ まとめ・個人のブログ・掲示板。
   弱い出どころしか無ければ「確かめられない」にする。

**出どころどうしが食い違うとき**: 強いほう（一次の資料・論文の書誌・公的機関）に合わせる。文章の出典のほうが誤りとみられるなら、判定は「食い違う」にして、
根拠に両方の原文を引用し、直し方に「出典を差し替える」と書く。強さが同じで決められないなら「確かめられない（説が割れている）」。

検索が使えないときは、文章の出典と、そこからたどれるページで確かめる。別の出どころで確かめられなかった主張は、根拠に「別の出どころでは未確認」と書く。

### 3. 判定を書く

| 判定 | いつ | 直し方 |
|---|---|---|
| 確認できた | 出どころの原文が、主張をそのまま支えている | — |
| 食い違う | 出どころと数字・年・名前・因果が違う | 出どころに合わせて直す |
| 言いすぎ | 出どころより強く言っている（「一部」が「すべて」、「可能性」が「原因」、「〜と言われる」が言い切りに） | 出どころの強さまで弱める |
| 確かめられない | 出どころが見つからない・弱い・説が割れている | 外す。残すなら「〜という説がある」とぼかし、割れていることを言う |
| 対象外 | 意見・感想・たとえ話・あいさつ・ボケ（直後に訂正されるもの）・これからの予定 | — |

```markdown
### C4 波の長さの 4 乗に反比例するの。青は赤の、約 5.9 倍よ。
- 場所: 48 行目（metan・青は散らばりやすい）
- 種類: 数字
- 判定: 確認できた
- 根拠: 「the amount of scattering is inversely proportional to the fourth power of the wavelength」。計算 (700÷450)^4 = 5.86（450nm と 700nm は文章の前提）
- 出典: https://en.wikipedia.org/wiki/Rayleigh_scattering （2026-10-02 に見た）
- 直し方: —
```

- 根拠は、引用（「」で囲む）か、計算の式。「正しい」「一般に知られている」は根拠にならない。
- 判定に迷ったら、弱いほう（確かめられない・言いすぎ）にする。
- 対象外にした理由も、根拠に一言書く（「ボケ。次のせりふで訂正される」）。訂正する側のせりふは確かめる。

### 4. 点検して、報告する

```bash
python3 <skill_dir>/claims.py verify <名前>.factcheck.md   # 根拠に書いた引用を、出典のページとまとめて照らす
python3 <skill_dir>/claims.py lint <名前>.factcheck.md     # 判定・根拠・出典・直し方の抜け
```

- `verify` の NG（引用がページに無い）と、`lint` の抜けが 0 になるまで直す。`verify` は、照らさなかった引用（10 字より短い「」・確かめている文と同じ言葉・出典の URL が無いもの）があれば、数と理由を出す。10 字より短い引用を確かめるときは `quote` で 1 つずつ照らす。根拠の「」には、出どころの原文だけを入れる（確かめている文章のほうの言葉は『』で囲む）。
- 別の出どころで確かめられなかった主張は、根拠に「別の出どころでは未確認」と書く。`lint` が「支えが弱い所」として並べるので、報告にも入れる。
- 報告は、**文章を直す所から先に**: 食い違う → 言いすぎ → 確かめられない の順に、主張・根拠・直し方。次に、確認できたが支えが弱い所。最後に判定の数。
- 確かめ役は文章を直さない（頼まれたときだけ直す）。書き手が直したら、直した主張だけもう一度確かめる。

## 事実の一覧を確かめる（書く前に止める）

調べた事実を一覧にしてから文章を書くとき（yukkuri-kaisetsu の `facts.md` など）は、一覧の各行に原文の引用を付けておくと、書く前に機械で照らせる。

```markdown
- [F8] 1869 年にティンダルが、小さな粒では青が赤より強く散らばることを見つけた。 — 原文: 「In 1869, … John Tyndall discovered」 — 出典: https://…
```

```bash
python3 <skill_dir>/claims.py verify <名前>.facts.md   # 「原文:」の引用が、同じ行の出典のページにあるか
```

「原文:」のある行は、全部照らす（`###` の小見出しで区切ってあっても、短い引用・数字だけの引用でも）。「原文:」の後に「…」が無い行・同じ行に出典の URL が無い行は、照らせなかったものとして数と理由が出て、OK にならない。

引用が通っても、事実の文が原文より強くなっていないか・数字が原文にあるかは、目で見る。

## 知っておくこと

- ファクトチェックは「書かれた主張が出どころに合うか」を見る。**書かれていない大事なこと**（都合の悪い事実の省き、反対の説）は、主張の一覧からは見つからない。
  念入りのときは、「この話で、ふつう触れられるのに書かれていないことは何か」を最後に 1 つ挙げる。
- 出どころ自体が誤っていることはある。2 つの独立した出どころが合っていれば「確認できた」でよいが、絶対ではない。
- PDF の引用を照らすには pypdf が要る（`pip install pypdf`）。
