# yukkuri-qa — 出来上がった動画を、手本の水準と照らす

台本の検査（yukkuri-script の `check.py`・`review.md`）と事実の確認（fact-check）は、台本の文章を見る。ここで見るのは、**作った動画そのもの**。

```
動画を作る（kaisetsu.py）→ qa.py で測る・画面を撮る → 別のエージェントが rubric.md で見る → 直す → もう一度（2 回まで）
```

## 手順

### 1. 測る

```bash
python3 <skill_dir>/qa.py 台本.txt                 # <台本名>.qa.md と、<台本名>_qa/sheet.jpg（画面の見本の一覧。既定 24 枚）
python3 <skill_dir>/qa.py 台本.txt --max-shots 36  # 長い動画は、撮る枚数を増やす
python3 <skill_dir>/qa.py 台本.txt --no-shots      # 数だけ
```

- 先に `kaisetsu.py 台本.txt --voicevox` で HTML を作っておく（画面は、その HTML を Chrome で開いて撮る）。
- `warn:` は直す所、`参考:` は知っておくこと。目安は `norms.json`（型ごと。出どころも書いてある）。

| 見るもの | 測り方 | 目安 |
|---|---|---|
| 構成 | 章の数と長さ、冒頭の章の長さ | 型ごと（列挙は 項目 1 つ 1 分半〜4 分・章 6〜10 個、物語は 1 章 2 分半〜7 分）。冒頭は 10〜90 秒 |
| 画面 | 絵のある時間の割合、同じ画面が続く長さ、最初の絵が出る時刻 | 9 割以上、冒頭 1 分は 15 秒・本編は 25 秒まで |
| 型 | 写真・図・吹き出しの画面の割合 | 列挙・物語・レビューは写真が半分以上、図解は図が半分以上、寸劇は吹き出しと語り手 |
| 字幕 | せりふの字数、1 分あたりの字数 | 1 つ 44 字まで（2 行）、1 分 280〜400 字 |
| 演技 | 同じ表情の続き、聞き手の反応の数 | 同じ表情は 6 せりふまで |
| 音 | BGM の有無と曲の数、効果音のきっかけの回数、声のファイル | 1 分に 3〜20 回、全部のせりふに声 |
| 仕上げ | ファクトチェックと見直しの結果、題・概要・サムネイル、いらすとやの点数 | — |

### 2. 目で見る（別のエージェントに渡す）

数では分からないもの（絵が話に合っているか・文字が読めるか・手本と並べて見劣りしないか）は、画面を見て判定する。
**作った本人はしない**（自分の作った画面は、よく見えてしまう）。`Agent`（`general-purpose`）に次の形で渡す。

```
<skill_dir>/rubric.md の観点で、<台本名>_qa/sheet.jpg（解説動画の画面の見本の一覧）を見て、採点してください。
先に読むもの: <skill_dir>/rubric.md、<台本名>.qa.md（測った値）、<台本名>.txt（台本。style: が動画の型）。
結果は <台本名>.qa.md の「目で見る」の下に書き足し、観点ごとの点数・総合の判定・直す所（何枚目の・何を・どう直すか）を報告してください。台本と動画は直さないでください。
```

### 3. 直して、もう一度

- 直す所を台本に反映し、動画を作り直して、`qa.py` をもう一度。目で見るのは 2 回まで（残った指摘は、使う人に伝える）。
- **音は、この手順では確かめられない**（BGM と声の大きさのつり合い・効果音が場面に合っているか・読み間違い）。使う人に、最初の 1 分と、山場を 1 か所、聞いてもらう。

## 知っておくこと

- 目安は、視聴回数の多い 22 チャンネルの静止画（約 500 コマ）と、目次のある 70 本の概要欄から取った。**動画を通して見た値ではない**
  （画面が替わる間隔・効果音の回数・BGM の音量は、制作者の解説記事の値）。くわしくは `../yukkuri-kaisetsu/research.md` の 12。
- 短い動画（3 分ほど）は、章の数と長さの目安を当てない。手本の解説は 9〜24 分が多い。
- 通ったからといって、面白い動画とは限らない。面白さは、題材と台本（yukkuri-script の見直し）で決まる。
