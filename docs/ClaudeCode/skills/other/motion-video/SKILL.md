# motion-video — 台本から、動画のように再生できる HTML を作る

同梱の `build.py`（Python3 / 標準ライブラリのみ）が、台本（JSON）・描画部（`engine.js`）・プレイヤーを 1 つの HTML にまとめる。
外部への依存は無い（書体は OS のもの、画像は data URI で埋め込む）。

- **描画は台本と時刻だけで決まる**。シーク・倍速・巻き戻しでも同じ画になり、同じ台本からは同じ動画になる。
- **表現は 3 つのモードから選ぶ**。どのモードでも、プレイヤー・時間割・字幕・音声は同じ仕組み（決定論的）。

| 表現（台本の `expression`） | 映像の作り方 | 向く場面 |
|---|---|---|
| `components` 部品 | 14 種の部品だけで組む。速く安く、毎回ぶれにくい | 定型の紹介・社内向け・短時間で |
| `mixed` 混在（既定） | 基本は部品。見せ場の 1〜3 場面だけ `custom` で描く | ほとんどの紹介・説明 |
| `free` 自由 | 場面ごとに `custom`（Canvas）か `dom`（HTML・SVG・CSS）で描く。**プレイヤー・時間割・字幕・音声だけを使い、中身は Claude が作る** | 作り込みたい紹介・公開する動画 |

- どの場面にも **重ねの層**（`overlays`: 注記・矢印・強調・スポットライト・バッジ・カーソル・OS 風の通知）と
  **カメラ**（`camera`: 寄る・引く・移る）を付けられる。部品の見た目を崩さずに演出を足す手段で、`custom` より先に使う。
- **字幕はナレーションから自動**で作り、場面の長さもナレーションの長さと部品の最低の長さから自動で決まる。

## 手順

### 0. 素材を集める
- 何を紹介・説明する動画か、誰が見るか、元になる資料（README・docs・メモ・画面の画像）を会話とリポジトリから集める。
- 素材が足りなければユーザーに確認する（何を伝える動画か、が分からないまま作らない）。

### 1. 選ばせる（`AskUserQuestion` を 1 回、最大 4 問）
呼び出す直前に、本文テキストへ次の 2 つの表を**必ず全件**出す（選択肢に載らないものも見せるため）。
`python3 <skill_dir>/build.py --list` の先頭にも同じ一覧が出る。

| プレイヤー | 見た目 | 向く場面 |
|---|---|---|
| `cinema` シネマ | 操作部は映像の上に重なり、再生中は隠れる | 紹介動画・ティザー |
| `studio` スタジオ | 操作部は映像の下、チャプターの一覧を下に並べる | 製品紹介・説明（既定） |
| `presenter` プレゼンター | 横にチャプターの目次と説明 | 研修・講義・長めの解説 |
| `minimal` ミニマル | 細いシークバーと最小限のボタン。速度・字幕・音声・チャプターは「⋯」 | 記事への埋め込み・短い動画 |
| `kiosk` キオスク | 自動再生・繰り返し・音なしで始まる。操作部は触れたときだけ | 展示・受付の画面 |
| `theater` シアター | 暗い地に大きな映像、横に文字起こし（クリックでその位置へ・検索） | 講演・録画の公開・長い解説 |
| `slides` スライド | 章の終わりで止まり、「次へ：章の名前」で進む | 発表の場で話しながら送る |

| 配色 | 性格 |
|---|---|
| `navy-brass` 紺と真鍮 | 紺の地に真鍮とターコイズ。落ち着いた製品紹介 |
| `midnight` 真夜中 | 黒に近い地にシアンと紫。技術・開発者向け |
| `daylight` 日中 | 白い地に青。社内説明・研修・明るい紹介 |
| `paper` 紙 | 生成りの地に焦げ茶と明朝の見出し。語り・解説 |
| `mono` モノクロ | 白黒に赤ひとつ。強い主張・キーノート |
| `vivid` 鮮やか | 深い紫の地に明るい差し色と丸ゴシック。広報・イベント |

質問（header の例）:

1. **プレイヤー**（「プレイヤー」）: 内容に合う 3 件（1 件目に「（おすすめ）」）＋`studio`。`studio` が 3 件に入っていれば次点。
2. **配色**（「配色」）: 内容・ブランドの色に合う 3 件（1 件目に「（おすすめ）」）＋`navy-brass`。同様。
3. **音声**（「音声」）: 読み上げ＋音楽＋効果音（既定）／読み上げだけ／音楽と効果音だけ（字幕で読む）／無音。
4. **表現**（「表現」）: 混在（既定・おすすめ）／部品だけ／自由（作り込む）。長さは聞かず、素材の量から標準（1〜2 分）を既定に決め、
   ユーザーが長さを言ったときだけ従う（4 問の上限のため。短め 30〜45 秒／標準 1〜2 分／長め 3〜5 分）。

引数や会話で明示されている項目は聞かない。ユーザーのブランドの色があれば、配色は近いものを選び、台本で `colors` を上書きしない
（上書きの口は無い。近いテーマを選ぶ）。

### 2. 台本を書く
`python3 <skill_dir>/build.py --list` で部品と書き方を確かめ、台本（JSON）を書く。骨組み:

```json
{
  "title": "動画の題名（ページの見出しにも出る）",
  "description": "ページに出す一文",
  "lang": "ja",
  "player": "studio",
  "theme": "navy-brass",
  "brand": { "name": "右上に出す名前" },
  "transition": "fade",
  "audio": { "narration": true, "music": "calm", "sfx": true, "rate": 1.1,
             "pronounce": { "Sodashitsu": "ソダシツ" } },
  "chapters": [
    { "title": "章の名前", "desc": "チャプターの一覧に出す説明",
      "scenes": [ { "type": "title", "title": "…", "narration": "…" } ] }
  ]
}
```

**章と場面の組み方**

- 章は 4〜7 個。1 章に場面 1〜3 個。長さの目安: 短め 4 章・場面 5 前後、標準 6 章・場面 8〜10、長め 7 章・場面 15〜25。
- 最初の場面は `title`、最後は `end` にする。
- 場面の選び方（内容 → type）:

| 伝える内容 | type |
|---|---|
| 題名・導入 | `title` |
| 一言で言い切る主張・問い | `statement` |
| できること・特徴（3〜5 個） | `bullets` |
| 処理・データ・依頼の流れ、差し戻し | `flow`（受け渡しは `travel`） |
| 手順・工程 | `steps` |
| コマンドの実行例 | `terminal` |
| 実績・効果の数字 | `stats` |
| 量の比較・推移 | `bars` |
| 前後・案の対比 | `compare`（`tone: good/bad`） |
| コードの解説 | `code`（`highlight` で行を順に強調し `note`） |
| アプリの画面・状態の変化・通知 | `window`（pane の `states`・`toasts`） |
| スクリーンショット・写真 | `image`（台本からの相対パス。埋め込まれる） |
| 締め・始め方・連絡先 | `end` |
| 機能・特徴を並べて（2〜6 枚） | `cards` |
| 年表・マイルストーン | `timeline` |
| AI とのやりとり・会話 | `chat` |
| 数値の推移 | `line` |
| 割合・内訳 | `donut` |
| 表での比較（行を順に強調） | `table` |
| 利用者の声・引用 | `quote` |
| 短い主張を語ごとに組み上げる | `kinetic`（`statement` より動きが強い） |
| 説明と数字・図を左右に | `split`（右に部品を縮小して置く） |
| 導入の前と後 | `beforeafter`（境目が動いて後の姿が現れる） |
| 上のどれにも当たらない絵 | `custom`（最後の手段。下記） |

- 同じ type を 3 場面続けない。
- 場面の切り替え（`transition`）は `fade`（既定）・`slide`・`zoom`・`wipe`（境目が左から右へ）・`push`（前の場面を押し出す）・`cut`。
  章の変わり目に `wipe`・`push` を使うと区切りが伝わる。多用しない。

**ナレーション（＝字幕）の書き方**

- 1 場面に 1〜2 文。話し言葉で、1 文は 40 字前後まで（長い文は読点で字幕が 2 つに分かれる）。
- 画面の文字とナレーションを同じにしない（画面は要点の語、ナレーションは説明の文）。
- `**強調**` は字幕では外れ、画面の部品では強調色になる。
- 読み上げで誤読しやすい語（製品名・英字のコマンド）は `audio.pronounce` に読みを入れる（字幕は元の表記のまま）。
- 場面の長さは自動（`duration` を書くと上書き。ナレーションが収まらなければ警告が出る）。

**モードごとの書き方**

- `components`: 部品と `overlays`・`camera` だけで組む。`custom` は使わない（使うと警告が出る）。
- `mixed`: 部品で組み、「部品では伝わりにくい見せ場」（画面の変化の様子・複数の画面の並び・独自の図）だけ `custom` にする。
  まず `overlays`・`camera` で足りないかを考え、足りないときに `custom`。
- `free`: 各場面を `custom` で描く。部品は `H.sub(type, spec, lt, d, {x, y, scale})` で縮小して並べる道具として使ってよい。
  ただし `title`・`end` は部品のままでもよい。

**dom（HTML・SVG・CSS で自由に描く）**

- `src`（HTML）・`cssSrc`（CSS）・`updateSrc`（毎コマ呼ぶ JS。本体 `(el, lt, d, H, s)`）を台本からの相対パスで書く（`html`・`css`・`update` に直接でもよい）。
- 1920×1080 の箱に描き、舞台の大きさに合わせて縮む。時刻は CSS 変数 `--lt`（場面の経過 ms）と `--p`（0..1）で受け取る。
- **CSS のアニメーションは一時停止にして、遅れを `--lt` で与える**（`animation-play-state: paused; animation-delay: calc(var(--lt) * -1ms)`）。
  こうすればシーク・倍速でも同じ画になる。JS で動かすなら `update` で `lt` から決める。
- `dom` の場面は、シークバーのプレビューと「WebM で保存」には映らない（Canvas だけが対象）。見せ場に使い、全場面を `dom` にしない。

**custom（Canvas に自由に描く）**

- 本体 `(ctx, lt, d, H, s)`。`lt` は場面の中の経過 ms、`d` は場面の長さ ms、`s` は台本の場面、`H` は描画の道具
  （一覧は `python3 <skill_dir>/build.py --api`、手本は `recipes.md`、実物は `examples/scenes/*.js`）。
- JS は **`src` に .js のパス**（台本からの相対）で書くのが基本。短いものは `code` に文字列か行の配列。
- **時刻だけで決まる描き方にする**（`Math.random` → `H.rand(種)`、`Date.now`・前のコマの状態・DOM の操作は使わない）。
- 座標は 1920×1080。大事な文字は縦 120〜880 に収める（下は字幕）。色は `H.C` の配色だけ。
- 長いデータ（行・名前の配列・部品の spec）は台本の場面 `s` に置き、JS は描き方だけにする。

### 3. 確かめて作る

```bash
python3 <skill_dir>/build.py spec.json --timeline      # 場面の長さ・字幕の時刻・合計（HTML は作らない）
python3 <skill_dir>/build.py spec.json -o out.html      # HTML を作る（--player / --theme で上書き可）
```

- `--timeline` で、合計の長さが選んだ長さに収まるか、字幕の切れ方が不自然でないかを見る。直すのは台本だけ。
- エラー（不明な type・必須の項目の欠け・画像が無い）は台本を直してから作り直す。
- 作ったら 1 回だけ開いて見る（場面の文字のはみ出し・重なり）。直すのは台本の文言・項目の数・`custom` の JS で、`engine.js` は触らない。
- `custom` の場面は、シークして途中の画を 2〜3 点見る（時刻だけで描けていれば、どこから見ても崩れない）。

### 4. 渡す
- 出力した HTML の場所を伝える。`SendUserFile` で渡すと確かめやすい。
- 「読み上げの声は見る人のブラウザと OS のものを使う（声が無い環境では効果音と音楽だけ）」と一言添える。

## プレイヤーの操作（全テンプレート共通）

| 操作 | ボタン | キー |
|---|---|---|
| 再生・一時停止 | ▶／❚❚、映像のクリック | `Space`・`K` |
| 停止（最初に戻る） | ■ | `S` |
| 5 秒戻る・進む | シークバー | `←`・`→` |
| 前・次のチャプター | ⏮・⏭、チャプターの一覧 | `[`・`]` |
| 速度（0.5〜2 倍） | 選択欄 | `<`・`>` |
| 字幕のオン・オフ | 字幕 | `C` |
| 音声のオン・オフ | スピーカー | `M` |
| 全画面 | ⛶ | `F` |

- シークバーはチャプターごとに区切られ、触れると時刻とチャプター名が出る。キーボードでも操作できる（`Home`・`End`・`PageUp/Down`）。
- 速度・字幕・音声の選択は、見る人のブラウザに保存される。
- 読み上げは、再生・倍速に合わせて字幕の区切りごとに話す。シークしたときは次の字幕から話す。
- **読み上げが字幕の時間に収まらないときは、読み終わるまで動画がその位置で待つ**（声の速さは OS とブラウザで違うため）。
  一時停止・シーク・停止で待ちは解け、声が無い環境では待たない。待たせたくない（映像の時間を優先する）ときは `audio.wait: false`。
- 場面の長さの見積もりは、`audio.pronounce` で置き換えた後の読み方の文字数で数える（読みが長くなる語も含めて見積もる）。

## プレイヤーの機能（全テンプレート共通）

- **シークバーのプレビュー**: 触れた時刻の画を小さく描く（描画が時刻だけで決まるので、その場で 1 コマ描ける）。
- **文字起こし**: `theater` で横に出る。クリックでその位置へ、検索で絞り込み。
- **続きから再生**: 前回の位置を見る人のブラウザに覚え、次に開いたとき「前回の続き（m:ss）から再生」を出す。
- **設定（⚙）**: 字幕の大きさ（小・標準・大）、小窓で再生（ピクチャー・イン・ピクチャー）、**動画ファイル（WebM）で保存**
  （最初から 1 倍速で再生しながら録画。字幕は映像に焼き込み、音楽と効果音は入り、読み上げの声は入らない）。
- **キー**: `J`・`L` で 10 秒、`0`〜`9` で 0〜90% の位置へ（上の表の操作に加えて）。
- **1 ページに複数のプレイヤー**: 1 つを再生すると、ほかは止まる。

## ほかの HTML に埋め込む

```bash
python3 <skill_dir>/build.py spec.json --embed -o intro.embed.html   # 断片（CSS と実行部を含む。何個並べてもよい）
```

- md-to-doc の文書には `<!--MD2DOC-VIDEO src="spec.json" player="minimal"-->` と書けば、文書を作るときに埋め込まれる。

## メモ

- 画面の比率は 16:9（1920×1080 の座標で描き、表示の大きさに合わせて拡大縮小する）。
- `image` の画像は data URI で埋め込むので、画像が多い・大きいと HTML が大きくなる。
- 読み上げの声が無い環境（例: 声の入っていない Linux）では、効果音と音楽だけになり、その旨がプレイヤーの下に出る。
- 絵文字のアイコン（`bullets` の `icon`）は OS の絵文字の書体で描く。絵文字の書体が無い環境では四角になる。
- 見本: `examples/showcase.json`（追加した部品・切り替え・`dom` の場面をすべて使う。`theater`）・`examples/sodashitsu.json`（部品だけ）・`examples/sodashitsu-mixed.json`（混在。pane が割れて増える・ブラウザと端末版の並び・
  SSH の線・OS 風の通知・カメラ・注記を `custom` と `overlays` で）。
- テーマを足すときは `build.py` の `THEMES` に 1 つ足す（canvas の配色・書体・背景の模様・操作部の配色）。
- 部品を足すときは `engine.js` の `R.<type>` と、`build.py` の `SCENE_TYPES`（必須の項目・説明・例）と `MIN_SEC` に足す。
