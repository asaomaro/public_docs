## 1. 文書は実態に追いついているか

**廃止は利用者の判断**。私（主エージェント）が挙げた 4 つの理由——移植できない／手順書が 2 つ同時に走る／
承認対象（plan file）が帳簿の外に出る／`metrics` に残らず測れない——を確認したうえでの決定。
read-only の強制自体が係争中（`anthropics/claude-code#19874` ほか）だったこと、
**OSS の SDD 陣営（Spec Kit / cc-sdd）も plan モードを使っていない**ことも材料になった。

置き換えたのは**促す中身だけ**で、判定（対象工程・`profile: light` 除外・`has_approver()`）は不変。
ただし**工程の選び方の根拠は立て直した**——以前の拠り所は `ExitPlanMode` の用途規定だったので、
機構ごと無くなると根拠も消える。新しい根拠は「**成果物が複数の案から選ぶものか**」。

**検査は捨てずに付け替えた**。`L9`（判定条件の写しを正典の外に作らない）は**失敗の型が主題に依らない**ので
主題だけ付け替え、`L10` には**退役の見張り**を足した。廃止で検査を 1 つ失うのは、
「規律は残す」という判断と噛み合わない。

## 3. 実走（サブエージェント）

テスト PJ（`scratchpad/pjretire2`・`mode: autonomous` / `humanGates: [design]`）で
`requirements → design → tasks` を 1 本完走。`verify --strict` exit 0。
**PJ はハーネスの現状から作り直した**——前回のコピーは design 点検を入れる前のもので、
新しいテンプレートを踏まないため。

**実走が「在るのに効かない」欠陥を突いた（最重要）**。`aidev doccheck start` が印字する観点は
工程を問わず固定の 5 項目で、`protocol-check.md` に足した新しい観点が**そこに入っていなかった**。
`--mode delegated` の点検者が読むのは CLI の出力なので、**別コンテキストへ委譲した瞬間、
新しい観点は一度も使われない**。実走は同一セッションで正典を直読していたから使えただけだった。
→ `design` のときだけ追加行を出すよう sh / ps1 を直し、design で出て tasks で出ないことを両実装で実測。
**散文に足しただけでは第二層に載らない**——載せる場所は CLI の出力側だった。

ほか実走の指摘（すべて反映）:
- **促しに提示先が無い**。「承認を得る」としか言わず、どこに提示するかが決まらないので実走は自分で決めた。
  会話で済ませると記録に残らず、**廃止理由に挙げた plan モードの欠点をそのまま引き継ぐ**。
  → `decisions.md` に書いて提示する、と促しと正典の両方に明記。
- **依拠する既存の実装が無い場合**（全面新規）が未定義で、指定した出所の形では**否定を書けなかった**。
  → 「`該当なし` と、そう言える根拠（探した範囲）を書く／節ごと省かない」。出所の書式も `tasks.md` の
  `対象:` 欄に揃えた。
- **承認者がいる判定でも返事が返らない**場合（無人の `autonomous` × `humanGates`）の扱いが無かった。
  → 止めずに `decisions.md` に書いて進み、承認は既存の approve ゲートが受ける。
  `humanGates` の意味自体は変えていない。
- plan モード前提の現役記述を製品中立に書き換え（`defaultMode: plan` は Claude Code の例に降格）。

## 追記: CI だけが赤かった（ロケール依存）

着地直前、**手元は緑・CI（ubuntu / pwsh）だけ `fail=12`** になった。原因は L10 の「同名の並び」検査で、
コメントが「間隔は**バイト数**で数える（`LC_ALL=C`）」と書いているのに、
**`LC_ALL=C` が `sort` にしか掛かっておらず `grep` 自身には掛かっていなかった**。
UTF-8 では `{1,30}` が 30 **文字**を見るので、日本語 13 文字（37 バイト）の間隔まで拾い、
無関係なコメント行（`bin/aidev:1984`）を退役名の並びとして赤にしていた。
C ロケールの手元では 37 バイト > 30 で一致せず、**原理的に再現しない**。
土台の lint が赤くなると「複製そのままでは通る」系の probe が総崩れになるので、
**1 件の誤検知が 12 件の fail に膨らんでいた**。

- `LC_ALL=C` を `grep` 自身に掛け、コメントどおりのバイト意味に固定した。
- `run.sh` に「**同じ lint を UTF-8 ロケールでも回す**」検査を足した。CI だけが捕まえられる
  状態だったので前倒しする（UTF-8 ロケールが無い環境では skip として申告する）。

**この型はこのラウンドで 2 度目**。独立監査が `[へに]` のブラケット式で同じ罠を実測しており、
そのときは C ロケールで**バイト集合になって検査が黙る**側だった。今回は逆向きで、
UTF-8 で**文字数になって誤検知する**側。どちらも「**環境で意味が変わる正規表現を書かない**」に集約される。

**この増分の検証**: 手元で **C / C.utf8 の両方**で `pass=1068 fail=0 skip=0` を実測し、CI でも確認した。
**サブエージェント実走はやり直していない**——変更したのは lint とテストの層だけで、
工程の手順・成果物・promptのどれも変わらないため、上の実走で見たものがそのまま成立する。
（`aidev` / `aidev.ps1` の振る舞いに触れる変更なら、やり直す。）
