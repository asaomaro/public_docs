## 1. 文書は実態に追いついているか

`lint-docs.sh` は L1〜L8 すべて pass。中身の追随は以下を直した。

- **`aidev-20-spec` / `aidev-25-design` の手順**: 「plan モードを使ってよい」→
  「**書く前に plan モードへ入る**」。役割だけの言い方（「方針を先に固める」等）では
  **丁寧に計画するだけでモードは切り替わらない**ため。
- **`aidev-00-start/SKILL.md`「三層判定」**: 同じ理由で「使ってよい」→「入る」。
  実走が「**読む順で最初に出会う plan モードの記述がここで、後続の命令形が減衰する**」と指摘した。
- **`protocol-autonomous.md`「plan モードとの関係」**: 「使う／使わない」→「入る／入らない」。
  入り方（`EnterPlanMode` / `Shift+Tab` / `/plan`）と、**抜けた先は元のモードではない**ことを明記。
  同ファイル内で「任意」「取れる」と可能形が残っていた行（実走が D-3 として指摘）も命令形に揃えた。
- **`allowed-tools`**: 「plan モードへ入れ」と命じる 3 つの skill に `EnterPlanMode` / `ExitPlanMode` を追加。
  実走が「**命令した動作を frontmatter が禁じている**」（D-1）と指摘した。
- **`DESIGN`「2.」**: 裏取りの結果を記録（下記「裏取り」）。行数予算 3417→3422（理由は `lint-docs.sh`）。

### 裏取り（散文に「できる／できない」を書く前に確かめたこと）

| 論点 | 結論 | 根拠 |
|---|---|---|
| フック・設定からモードを切り替える | **できない** | hooks の JSON 出力に該当項目・イベントが無い。要望 anthropics/claude-code#31579・#14044 は未実装 |
| skill から入る | **できない** | anthropics/claude-code#37446 が **closed as not planned** |
| `permissions.defaultMode: plan` | **セッション開始時のみ** | 「new sessions start in」 |
| エージェント自身が入る | **できる** | `EnterPlanMode` は主エージェントのツールで、定義自身が「use proactively」 |
| 元のモードへ戻る | **できない** | 「Approving a plan exits plan mode and **switches the session to the permission mode each approve option describes**」 |
| SDK ホストからの切替 | **できる**（第三層） | `setPermissionMode()`：「takes effect immediately for all subsequent tool requests」 |

**`permissionMode: plan` のサブエージェントへ委譲する案は、検討して退けた**。
「工程の間だけ切り替えて元に戻す」を技術的には満たすが、サブエージェントからは
`AskUserQuestion` / `EnterPlanMode` / `ExitPlanMode` が **`tools` に書いても除去され**、
会話履歴も見えない。**plan モードの価値は read-only であることではなく探索中の往復**
（要件を詰め直す・「No, keep planning」で差し戻す）なので、委譲した時点でその価値が消える。
残るのは read-only の一発調査で、それは `protocol.md`「2.6」の委譲として既にある。

**他実装でも同じ落とし穴がある**ことも確かめた——Codex CLI は `/plan`・Shift+Tab で入る
read-only の計画状態で `approval_policy: never` なら同じ形、Copilot は
microsoft/vscode#312668「Plan-mode restrictions despite agent mode and approved handoff」として
**現に詰まった報告がある**。1 実装の癖ではないので、規約として書く価値がある。
