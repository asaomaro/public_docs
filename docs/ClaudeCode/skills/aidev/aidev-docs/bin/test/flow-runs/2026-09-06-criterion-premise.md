## 1. 文書は実態に追いついているか

外部レビュー（`retro/20260906-planmode-criterion.md`）の指摘 1 件は**正しく、しかも一段強い**。

判断基準（「二重ゲートに見合うか」）は「同じものを承認するなら二重だから入らない」と結論するが、
**これは既存のゲートが機械で止まることを前提**にしている。止まらないゲートしか無い工程・環境では、
plan モードは二重化ではなく**ゲートの実体化**になり、同じ基準から逆の結論が出る。

レビューは根拠に別リポジトリの教材キットを挙げているが、それはこのリポジトリに無い。
代わりに **aidev 自身の可搬性契約**で検証した——`protocol.md`「2.10」の第二層は
「全環境（**CLI 無しなら手で同等に**）」と書いており、**ハーネス自身が CLI の無い環境を
想定範囲に入れている**。移植先の話ではなく、契約の内側の問題だった。

### 実走が見つけた、足した文章そのものの欠陥（2 件とも自分で作ったもの）

| # | 欠陥 | 対応 |
|---|---|---|
| (a) | **「2.10 が『手で同等に』と認めている」が 2 通りに読めた**——(i) 手のゲートは機械の停止に当たらない＝前提は崩れる／(ii) 2.10 が「CLI 無しでも第二層は効く」と保証している＝崩れない。**正典に決着が無く、実行時に読まない `DESIGN.md` にしか無かった** | **判定を 1 つに固定**——`aidev guard <工程>` が exit≠0 で止まるか。「手で同等に」は**人がやる**という意味なので止まらない側、と明記 |
| (b) | **新しい行だけを読むと「入る」に倒れるが、下の「承認者がいない工程で入ると抜けられない」と衝突する**。読んだ実行者は入って詰む | **見る順を明記**——(1) 承認者がいるか（いなければ入らない）→ (2) 二重ゲートに見合うか |

(b) は「規約を足したら別の規約と矛盾した」型で、**足した本人には見えない**。
基準だけを読ませて 3 問に答えさせる、という実走の設計が効いた。
