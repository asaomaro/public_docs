# テスト結果テンプレート

`sdd-verify` が `.sdd/<機能名>/test-result.md` を書くときの書式です。
**このファイルは書き換えて構いません。** 書式を変えれば出力も変わります。

> 使うのは下の「テンプレート」節だけ。末尾の「記入例」は人間向けの参考で、**出力に写さない**こと。

---

## テンプレート

```markdown
# <機能名> テスト結果

## ラウンド <n>（<YYYY-MM-DD HH:MM>）

対象: <ブランチ名 / コミット / 「作業ツリー」>

| # | 受け入れ条件 | 判定 | 根拠 |
|---|---|---|---|
| 1 | <spec.md の条件をそのまま写す> | ○ | <テスト名 / ファイル:行 / 操作して見た結果> |

**結果: <N>件中 <M>件（○ <M> / × <X> / − <U>）**

### 満たさなかった条件

- **#<番号> <条件>**
  - 起きたこと: <期待と実際>
  - 原因: 実装不足 / 条件が曖昧 / 条件が誤り
  - 次にすること: <戻る先のコマンドと、具体的に何をするか>

### 仕様の外で気づいたこと

- <合否には数えないが伝えるべきこと。無ければ「なし」>
```

---

## 書き方の規則

### 判定は3値

| 記号 | 意味 |
|---|---|
| ○ | 満たす。**根拠を示せた**もの |
| × | 満たさない |
| − | **未確認**（実装が途中・確かめる手段が無い等） |

**「実装したのだから満たしているはず」は根拠ではありません。** 根拠を示せない条件は
`○` にせず、`×` か `−` にします。

### 根拠の書き方

| 確かめ方 | 根拠に書くこと |
|---|---|
| テストを走らせた | テスト名と結果（例: `search.test.js: 3 passed`） |
| コードを読んだ | ファイルと該当箇所（例: `src/App.jsx:42-48`） |
| 手で操作した | **何をして何が見えたか**（例: 「zzz」を入力 → 一覧が空、「該当なし」表示） |

「確認済み」「問題なし」だけでは根拠になりません。**追試できる形**で書きます。

### ラウンドは追記する

再検証したら**新しいラウンドとして下に追記**し、前のラウンドは消しません。
何が直って何が残ったかの経過が、そのまま記録になります。

### 受け入れ条件は spec.md から写す

条件の文言は `spec.md` のものをそのまま使います。言い換えると、
**どの条件のことか分からなくなり**、spec.md との対応が切れます。

## 記入例（出力には写さないこと）

```markdown
# memo-search テスト結果

## ラウンド 1（2026-08-31 14:20）

対象: 作業ツリー

| # | 受け入れ条件 | 判定 | 根拠 |
|---|---|---|---|
| 1 | 「会議」で本文に含むメモだけ出る | ○ | メモ3件（うち1件が「会議」含む）で入力 → 1件のみ表示 |
| 2 | 空にすると全件に戻る | ○ | 上の状態から空に → 3件表示 |
| 3 | 0件のとき「該当なし」 | × | 「zzz」入力 → 一覧は空になるが文言が出ない |
| 4 | 「カイギ」と「かいぎ」は別物 | ○ | `src/App.jsx:44` で toLowerCase のみ。かな変換なし |
| 5 | 大文字小文字は区別しない | − | 「Meeting」を含むメモが未作成で未確認 |

**結果: 5件中 3件（○ 3 / × 1 / − 1）**

### 満たさなかった条件

- **#3 0件のとき「該当なし」**
  - 起きたこと: 一覧は空になるが、「該当なし」の文言が表示されない
  - 原因: 実装不足
  - 次にすること: `sdd-implement` に戻る。tasks.md の3が未完了のまま `[x]` になっている

### 仕様の外で気づいたこと

- 検索欄の入力ごとに全件を走査している。件数が増えると重くなる可能性
  （現状の件数では体感なし。spec.md の条件外なので合否には数えない）
```
