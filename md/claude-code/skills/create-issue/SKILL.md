以下の手順で GitHub issue を作成し、対応するブランチに切り替えてください。

**issue の内容**: $ARGUMENTS

## 手順

### 1. ローカル変更の確認とスタッシュ

`git status --porcelain` を実行し、変更があるか確認する。

変更がある場合:
- `git diff HEAD` で変更内容を確認する
- diff の内容から、変更の概要を表す簡潔な日本語のスタッシュメッセージを考案する（例: "ログイン画面のバリデーション修正中"）
- `git stash push -m "考案したメッセージ"` でスタッシュに退避する
- スタッシュしたことをユーザーに報告する

変更がない場合はそのまま次の手順へ進む。

### 2. GitHub issue の作成

`$ARGUMENTS` の内容を元に、適切なタイトルと本文を考えて以下のコマンドで issue を作成する:

```
gh issue create --title "タイトル" --body "本文"
```

- タイトル: 内容を端的に表す日本語の一文（〜の追加 / 〜の修正 / 〜の不具合 など）
- 本文: 実装内容や背景、完了条件を簡潔に記述

### 3. ブランチの作成と切り替え

作成された issue の番号を取得し、issue の内容に応じてプレフィックスを選択してブランチを作成・切り替える:

```
git switch -c {プレフィックス}/issue-{番号}
```

プレフィックスの選択基準:

| プレフィックス | 使用する場面 |
|--------------|------------|
| `feature/`   | 新機能の追加・機能改善 |
| `fix/`       | バグ修正・不具合対応 |
| `hotfix/`    | 本番環境の緊急修正 |
| `chore/`     | 設定変更・依存関係更新・ビルド関連 |
| `refactor/`  | リファクタリング（機能変更なし） |
| `docs/`      | ドキュメントのみの変更 |

### 4. 完了報告

- スタッシュしたかどうか
- 作成した issue のタイトルと番号・URL
- 切り替えたブランチ名（選択したプレフィックスの理由も添える）

を簡潔にユーザーへ報告する。
